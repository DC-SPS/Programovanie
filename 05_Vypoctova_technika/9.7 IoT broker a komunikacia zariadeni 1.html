9.7 IoT broker a komunikácia zariadení 1

IoT – architektúra, komunikácia a bezpečnosť · 45 minút

Praktické prostredie: Ukážky Wi-Fi na ESP32 možno spustiť v online simulátore. Príkazy pre broker a Raspberry Pi určené na lokálnu laboratórnu sieť spúšťajte len na zariadeniach, na ktoré máte oprávnenie. V príkladoch nepoužívajte skutočné heslá ani tokeny.

Ciele hodiny

Žiak má vedieť:

  • prakticky použiť MQTT broker,
  • publikovať a odoberať správy,
  • overiť retained správanie,
  • vysvetliť rozdiel medzi lokálnym a sieťovým prístupom,
  • diagnostikovať základný problém komunikácie.

1. Laboratórna architektúra

0 – 5 min

Platforma: text

Publisher → Mosquitto broker → Subscriber

Na prvú ukážku môžu všetky časti bežať na jednom Raspberry Pi. Potom použijeme pripravený sieťový broker.

2. Príprava

5 – 14 min

Na Raspberry Pi OS môže učiteľ pripraviť:

Platforma: bash

sudo apt update
Dokumentácia Raspberry Pi

Platforma: bash

sudo apt install mosquitto mosquitto-clients
Dokumentácia Raspberry Pi

Overenie služby:

Platforma: bash

systemctl status mosquitto
Dokumentácia Raspberry Pi

Predvolená konfigurácia moderného Mosquitto môže povoľovať iba lokálny prístup. Nainštalovanie preto automaticky nesprístupní broker celej sieti.

Na sieťové cvičenie učiteľ pripraví listener, účty a prístupové práva. Broker nevystavujeme verejne ako anonymnú službu.

3. Prvá správa

14 – 26 min

V prvom termináli:

Platforma: bash

mosquitto_sub \
  -h localhost \
  -t 'skola/ucebna01/temperature' \
  -v
Dokumentácia Raspberry Pi

V druhom termináli:

Platforma: bash

mosquitto_pub \
  -h localhost \
  -t 'skola/ucebna01/temperature' \
  -m '23.6'
Dokumentácia Raspberry Pi

Odberateľ zobrazí tému a obsah.

Experiment

  1. Ukonči odberateľa.
  2. Publikuj novú bežnú správu.
  3. Znovu spusti odberateľa.

Pri tomto jednoduchom odbere bez zachovanej relácie a bez retained správy sa stará správa automaticky nezobrazí.

4. Retained a zástupné filtre

26 – 34 min

Publikovanie posledného stavu:

Platforma: bash

mosquitto_pub \
  -h localhost \
  -t 'skola/ucebna01/status' \
  -m 'online' \
  -r
Dokumentácia Raspberry Pi

Nový odber:

Platforma: bash

mosquitto_sub \
  -h localhost \
  -t 'skola/ucebna01/#' \
  -v
Dokumentácia Raspberry Pi

Mal by dostať uloženú retained správu.

Vymazanie retained obsahu danej témy:

Platforma: bash

mosquitto_pub \
  -h localhost \
  -t 'skola/ucebna01/status' \
  -r \
  -n
Dokumentácia Raspberry Pi

Tieto príkazy používame na vlastných laboratórnych témach.

5. Dve zariadenia

34 – 41 min

Učiteľ poskytne:

  • adresu brokera,
  • spôsob autentifikácie,
  • CA certifikát pri TLS,
  • povolený prefix tém.

Každá skupina použije vlastný priestor:

Platforma: text

vyuka/skupina01/temperature
vyuka/skupina02/temperature

Pri ESP32 alebo inom klientovi nastavíme jedinečné client ID. Dve pripojenia s rovnakým client ID môžu viesť k odpájaniu predchádzajúceho klienta.

Diagnostický postup

  1. Je zariadenie pripojené do siete?
  2. Je broker dostupný?
  3. Sú správne údaje a TLS nastavenie?
  4. Má klient právo na tému?
  5. Zhoduje sa téma a filter?
  6. Nie je duplicitné client ID?

6. Zápis

41 – 45 min

Broker smeruje správy medzi klientmi.

mosquitto_pub publikuje, mosquitto_sub odoberá.

Lokálny prístup a sieťový listener sú rozdielne konfigurácie.

Retained správa poskytuje posledný uložený stav témy.

Každé zariadenie má mať vhodnú identitu a pridelené oprávnenia.
