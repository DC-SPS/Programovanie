4.8 Watchdog timer

Automatický dohľad nad chodom zariadenia a obnova po zablokovaní programu.

Tematický celok 4Výpočtová technikaAVR · Arduino · ESP32 · Raspberry Pi45 minút

Predmet: Výpočtová technika
Ročník: tretí, stredná škola
Trvanie: 45 minút
Platformy: AVR, Arduino, ESP32 a Raspberry Pi
Nadväznosť: Časovače a časovanie

Ciele hodiny

Po hodine má žiak vedieť:

  • vysvetliť účel watchdog časovača,
  • opísať princíp pravidelného potvrdzovania činnosti programu,
  • rozpoznať správne a nesprávne umiestnenie obsluhy watchdogu,
  • vysvetliť rozdiel medzi resetom a odstránením chyby,
  • porovnať watchdog na mikrokontroléri a počítači s Linuxom.

1. Čo ak sa program zasekne?

Čas: 0 – 5 min

Predstavme si zariadenie, ktoré meria teplotu v skleníku a ovláda ventilátor.

Program sa dostane do nekonečného čakania:

while (!senzorPripraveny()) {
  // Čakanie bez časového limitu.
}

Ak snímač pre poruchu nikdy neohlási pripravenosť:

  • program nepokračuje,
  • nové meranie sa nevykoná,
  • riadenie ventilátora sa neaktualizuje.

Pri zariadení nemusí byť človek, ktorý stlačí reset.

Watchdog timer umožňuje obnoviť činnosť zariadenia, keď program prestane správne postupovať.

Otázka pre triedu

Aké zariadenia by mali vedieť obnoviť svoju činnosť bez zásahu človeka?

Možné odpovede: meteorologická stanica, zavlažovanie, sieťový prvok, vzdialený snímač alebo domáca automatizácia.

2. Princíp watchdog časovača

Čas: 5 – 12 min

Watchdog timer, skrátene WDT, je dohľadový časovač.

Program musí pred uplynutím nastaveného intervalu pravidelne potvrdiť, že pracuje správne.

Táto operácia sa označuje ako:

  • obnovenie watchdogu,
  • obsluha watchdogu,
  • „kŕmenie“ watchdogu,
  • feed, kick alebo refresh.

Normálna činnosť

Spustenie watchdogu
        ↓
Program vykoná potrebné úlohy
        ↓
Potvrdí správny priebeh
        ↓
Časový interval sa začne odznova
        ↓
Program pokračuje

Zaseknutie programu

Program sa zasekne
        ↓
Nepotvrdí činnosť
        ↓
Uplynie časový limit
        ↓
Watchdog vyvolá nastavenú reakciu

Typickou reakciou je reset zariadenia. Niektoré watchdog mechanizmy umožňujú aj prerušenie, diagnostický výpis alebo inú reakciu.

Príklad s intervalom dve sekundy

Program potvrdzuje činnosť približne každých 100 ms.

Ak sa zasekne, potvrdenia prestanú prichádzať. Približne dve sekundy po poslednom potvrdení watchdog zasiahne.

Časový limit má určitú toleranciu podľa použitého hardvéru.

Dôležité rozlíšenie

Watchdog neopravuje chybu programu. Resetuje alebo inak obnoví systém, ktorý prestal správne pracovať.

Ak sa po každom štarte zopakuje rovnaká chyba, zariadenie môže skončiť v opakovanom resetovaní.

3. Pravidlá správneho používania

Čas: 12 – 19 min

Pravidlo 1: Potvrdzujeme vykonanie práce

Potvrdenie má znamenať:

Dôležité úlohy prebehli a program môže pokračovať.

Vhodný princíp:

nacitajVstupy();
aktualizujRiadenie();
nastavVystupy();

obnovWatchdog();

Samotné potvrdenie však ešte neoveruje správnosť výsledkov. Program musí podľa potreby kontrolovať aj platnosť údajov a stav zariadenia.

Pravidlo 2: Watchdog neobsluhujeme bezpodmienečne z ISR

Nevhodný princíp:

ISR(TIMER1_COMPA_vect) {
  obnovWatchdog();
}

Hlavný program sa môže zaseknúť, ale časovačové prerušenie ďalej obnovuje watchdog.

Watchdog potom nedokáže odhaliť zastavenie hlavného programu.

Podobný problém vznikne, keď watchdog obnovuje samostatná úloha bez kontroly ostatných dôležitých úloh.

Pravidlo 3: Zvolíme primeraný časový limit

Príliš krátky limit Príliš dlhý limit
Resetuje aj správne fungujúci program Poruchu odhalí neskoro
Nezohľadní legitímne dlhšie spracovanie Zariadenie zostane dlho bez riadenia

Limit vyberáme podľa najdlhšieho očakávaného správneho priebehu a požadovaného času reakcie na poruchu.

Dlhú operáciu je často lepšie rozdeliť na menšie kroky, medzi ktorými vieme overiť postup.

Pravidlo 4: Aj čakanie má mať časový limit

Najprv sa snažíme zabrániť nekonečnému čakaniu:

unsigned long zaciatok = millis();

while (!senzorPripraveny()) {
  if (millis() - zaciatok >= 200) {
    // Ohlásenie chyby a ukončenie čakania.
    break;
  }
}

Timeout operácie a watchdog sa dopĺňajú. Timeout rieši konkrétne čakanie, watchdog dohliada na postup systému.

Pravidlo 5: Po resete nastavíme bezpečný stav

Program musí pri štarte vhodne inicializovať výstupy a overiť stav zariadenia.

Počas resetu nemusia GPIO udržiavať predchádzajúcu úroveň. Pri riadení motora alebo ohrievača preto bezpečný stav nesmie závisieť iba od programu.

4. AVR a Arduino: praktická ukážka

Čas: 19 – 29 min

Watchdog na ATmega328P

Klasické Arduino Uno R3 používa mikrokontrolér ATmega328P.

Jeho watchdog využíva samostatný interný oscilátor, takže jeho počítanie nie je závislé od vykonávania hlavnej slučky.

Knižnica AVR poskytuje:

#include <avr/wdt.h>

Funkcia alebo konštanta Význam
wdt_enable(...) Zapnutie watchdogu a nastavenie intervalu
wdt_reset() Obnovenie watchdogu
wdt_disable() Vypnutie watchdogu, ak to konfigurácia umožňuje
WDTO_2S Nominálny interval približne dve sekundy

wdt_reset() neresetuje mikrokontrolér. Obnoví odpočítavanie watchdogu.

Zadanie

  • LED pravidelne bliká.
  • Hlavný program priebežne obnovuje watchdog.
  • Stlačením tlačidla zámerne vyvoláme zaseknutie.
  • Watchdog následne resetuje dosku.

Zapojenie

  • Tlačidlo medzi D2 a GND.
  • Použijeme zabudovanú LED.
  • Externé záťaže počas ukážky nepripájame.

Program pre Arduino Uno R3

#include <avr/wdt.h>

const byte TLACIDLO = 2;

unsigned long poslednePrepnutie = 0;
bool ledSvieti = false;

void setup() {
  // Bežná inicializácia pre Uno s aktuálnym bootloaderom.
  MCUSR = 0;
  wdt_disable();

  pinMode(TLACIDLO, INPUT_PULLUP);
  pinMode(LED_BUILTIN, OUTPUT);
  digitalWrite(LED_BUILTIN, LOW);

  Serial.begin(9600);
  Serial.println("Start programu");

  poslednePrepnutie = millis();

  wdt_enable(WDTO_2S);
}

void loop() {
  unsigned long teraz = millis();

  if (teraz - poslednePrepnutie >= 250) {
    poslednePrepnutie = teraz;
    ledSvieti = !ledSvieti;

    digitalWrite(
      LED_BUILTIN,
      ledSvieti ? HIGH : LOW
    );
  }

  if (digitalRead(TLACIDLO) == LOW) {
    Serial.println("Simulovane zaseknutie");

    while (true) {
      // Watchdog tu zámerne neobnovujeme.
    }
  }

  // Program úspešne prešiel kontrolovanou časťou slučky.
  wdt_reset();
}

Očakávaný priebeh

  1. Po zapnutí sa vypíše Start programu.
  2. LED mení stav približne každých 250 ms.
  3. Po stlačení tlačidla program uviazne v nekonečnej slučke.
  4. Watchdog sa prestane obnovovať.
  5. Približne po dvoch sekundách od posledného obnovenia nastane reset.
  6. Program sa spustí znova.

Ak tlačidlo zostane stlačené, program sa po štarte opäť zasekne. Pre ukážku ho krátko stlačíme a uvoľníme.

Poznámka k bootloaderu

Ukážka predpokladá Uno R3 s aktuálnym bootloaderom, napríklad Optiboot. Niektoré staršie bootloadery môžu po watchdog resete skončiť v resetovacej slučke.

Pri vlastnom AVR programe môže byť potrebné vypnúť zostávajúci watchdog už vo veľmi skorej inicializácii, ešte pred setup(). Riadky v setup() nenahrádzajú správne správanie bootloadera.

Otázka pre žiakov

Prečo watchdog zasiahne, aj keď v nekonečnej slučke zostávajú prerušenia povolené?

Odpoveď: Watchdog počíta nezávisle a žiadna časť programu ho počas zaseknutia neobnovuje.

5. Watchdog na ESP32

Čas: 29 – 35 min

ESP32 má viac dohľadových mechanizmov. Dva dôležité sú:

Mechanizmus Čo sleduje
Interrupt Watchdog Či nie je príliš dlho blokované vykonávanie potrebných prerušení
Task Watchdog Či sledované úlohy alebo registrovaní používatelia potvrdzujú činnosť včas

Konkrétne nastavenie a reakcia závisia od ESP-IDF, Arduino jadra a konfigurácie.

Interrupt Watchdog

Pomáha odhaliť napríklad:

  • príliš dlhú ISR,
  • príliš dlhú kritickú sekciu,
  • dlhé zakázanie prerušení.

Tým nadväzuje na pravidlo z predchádzajúcej hodiny:

ISR aj kritická sekcia majú byť krátke.

Task Watchdog

Sleduje prihlásené úlohy alebo iné registrované body dohľadu.

Typický postup:

Inicializácia alebo konfigurácia watchdogu
                  ↓
Prihlásenie sledovanej úlohy
                  ↓
Vykonanie práce
                  ↓
Potvrdenie činnosti

Medzi používané funkcie ESP-IDF patria:

esp_task_wdt_add(NULL);
esp_task_wdt_reset();

Prvá môže prihlásiť aktuálnu úlohu, druhá potvrdzuje jej činnosť. Nejde o kompletný program — watchdog musí byť správne inicializovaný a treba kontrolovať návratové hodnoty.

Podoba inicializačného API sa medzi verziami menila, preto kompletný kód prispôsobujeme nainštalovanej verzii ESP-IDF alebo Arduino jadra.

Dôležitý príklad

Úloha pravidelne vykonáva:

esp_task_wdt_reset();

Zároveň však úplne ignoruje poruchu snímača.

Zachytí watchdog chybnú teplotu?

Nie automaticky. Watchdog vidí včasné potvrdenia. Kontrolu zmysluplnosti teploty musí zabezpečiť program.

6. Raspberry Pi a Linux

Čas: 35 – 39 min

Na Raspberry Pi s Linuxom rozlišujeme dohľad nad:

  1. konkrétnou aplikáciou,
  2. celým systémom.

Dohľad nad aplikáciou

Správca služieb systemd môže aplikáciu znovu spustiť, keď skončí chybou.

Samotné nastavenie automatického reštartu však nemusí odhaliť proces, ktorý stále existuje, ale zasekol sa.

Na sledovanie takého prípadu môže aplikácia posielať pravidelné oznámenia služby watchdogu systemd. Musí na to byť pripravená a správne nakonfigurovaná.

Hardvérový watchdog

Podporovaný hardvérový watchdog môže resetovať celý počítač, ak nedostáva potrebné potvrdenia.

Linux ho môže sprístupniť napríklad cez:

/dev/watchdog
/dev/watchdog0

Dostupnosť závisí od modelu, ovládača a nastavenia systému.

Obsluhu môže zabezpečovať systémová služba alebo systemd.

Porovnanie

Druh dohľadu Typická reakcia
Dohľad nad aplikáciou Reštart konkrétnej služby
Hardvérový watchdog systému Reset celého počítača

Na dnešnej hodine zostávame pri vysvetlení princípu. Aktivovanie hardvérového watchdogu je konfiguračný zásah, ktorý môže pri chybe vyvolať reštart počítača.

Raspberry Pi Pico je mikrokontrolérová platforma a má odlišné možnosti a rozhrania než Raspberry Pi s Linuxom.

7. Úlohy pre žiakov

Čas: 39 – 43 min

A. Zachytí watchdog zaseknutie?

void loop() {
  while (!prisliData()) {
    wdt_reset();
  }

  spracujData();
}

Otázka: Čo sa stane, ak údaje nikdy neprídu?

Odpoveď: Program zostane čakať a stále obnovuje watchdog. Watchdog preto toto zaseknutie neodhalí.

Vhodná úprava: Zaviesť časový limit prijímania a po jeho prekročení vykonať definovanú reakciu na chybu.

B. Vyberte časový limit

Zdravý program dokončí kontrolovaný cyklus najneskôr za 300 ms. Uvažujeme intervaly:

  • 100 ms,
  • 1 sekunda,
  • 30 sekúnd.

Ktorý je z ponuky najvhodnejší?

Odpoveď: Jedna sekunda, ak poskytuje dostatočnú rezervu a vyhovuje požadovanému času reakcie. Sto milisekúnd je menej než dĺžka zdravého cyklu, tridsať sekúnd môže znamenať zbytočne neskoré odhalenie.

C. Opakované resety

Zariadenie sa po každom štarte pokúsi načítať snímač. Pri jeho poruche sa zasekne a watchdog ho resetuje.

Otázka: Odstránil watchdog príčinu poruchy?

Odpoveď: Nie. Po štarte treba rozpoznať chybu, použiť časový limit a prejsť napríklad do definovaného chybového režimu.

8. Overenie vedomostí a zápis

Čas: 43 – 45 min

Otázka Odpoveď
Na čo slúži watchdog? Na dohľad nad postupom programu a vyvolanie reakcie pri chýbajúcom potvrdení.
Čo znamená obnovenie watchdogu? Potvrdenie činnosti pred uplynutím limitu.
Opravuje watchdog chybu programu? Nie.
Prečo ho neobnovujeme bezpodmienečne z časovačovej ISR? ISR môže pokračovať aj pri zaseknutom hlavnom programe.
Čo spôsobí príliš krátky limit? Nežiaduce zásahy aj pri správnej činnosti.
Čo musíme riešiť po resete? Inicializáciu, stav zariadenia a príčinu poruchy.

Zápis do zošita

Watchdog timer je dohľadový časovač.
Program musí v stanovenom intervale potvrdzovať správny postup.
Ak potvrdenie nepríde, watchdog vyvolá nastavenú reakciu, často reset.
Potvrdenie má nadväzovať na vykonanie dôležitých úloh.
Watchdog neopravuje príčinu chyby a nenahrádza časové limity jednotlivých operácií.
Po resete musí zariadenie prejsť do definovaného stavu.

Nasledujúca hodina: GPIO — všeobecné digitálne vstupy a výstupy, logické úrovne a základné zapojenia.
