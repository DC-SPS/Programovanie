4.7 Časovače a časovanie

Meranie času, plánovanie činností a práca s časovačmi na rôznych platformách.

Platformy: AVR, Arduino, ESP32 a Raspberry Pi
Nadväznosť: Pravidlá práce v ISR a debouncing

Ciele hodiny

Po hodine má žiak vedieť:

1. Prečo zariadenie potrebuje merať čas?

Čas: 0 – 5 min

Mikrokontrolér často musí:

  • každú sekundu zmerať teplotu,
  • pravidelne aktualizovať displej,
  • po určitom čase vypnúť výstup,
  • generovať impulzy,
  • merať čas medzi dvoma udalosťami.

Predstavme si zariadenie, ktoré má zároveň:

  1. blikať LED,
  2. reagovať na tlačidlo,
  3. každé dve sekundy odoslať nameranú hodnotu.

Ak program pri každej úlohe dlho čaká, ostatné činnosti sa oneskorujú.

Časovanie určuje, kedy sa má činnosť vykonať. Nemusí pritom znamenať zastavenie programu.

Dva základné prístupy

Prístup Princíp
Blokujúce časovanie Program na danom mieste čaká
Neblokujúce časovanie Program kontroluje uplynutý čas a medzitým pracuje ďalej

Otázka pre triedu:
Ktorý prístup sme použili pri debouncingu bez delay()?

Odpoveď: Neblokujúce časovanie pomocou millis().

2. Blokujúce časovanie: delay()

Čas: 5 – 11 min

Príklad pre Arduino Uno

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_BUILTIN, HIGH);
  delay(500);

  digitalWrite(LED_BUILTIN, LOW);
  delay(500);
}

LED svieti približne 500 ms a ďalších 500 ms nesvieti.

Celá perióda blikania je približne 1 sekunda.

Čo znamená blokovanie?

Počas delay(500) hlavná slučka nepokračuje na ďalší príkaz.

Na Arduino Uno môžu počas bežného delay() naďalej prebiehať povolené prerušenia. Blokovanie hlavného programu preto neznamená zastavenie celého hardvéru.

Problém s tlačidlom

void loop() {
  digitalWrite(LED_BUILTIN, HIGH);
  delay(1000);

  digitalWrite(LED_BUILTIN, LOW);
  delay(1000);

  kontrolujTlacidlo();
}

Tlačidlo kontrolujeme iba približne raz za dve sekundy. Krátke stlačenie môžeme prehliadnuť.

Kedy je delay() vhodné?

  • pri jednoduchom skúšobnom programe,
  • pri krátkej inicializačnej postupnosti, ak čakanie neprekáža,
  • keď zariadenie počas čakania nemusí vykonávať ďalšie úlohy v danom vlákne.

Do bežnej ISR delay() nepatrí.

3. Neblokujúce časovanie: millis()

Čas: 11 – 18 min

V Arduino frameworku vracia millis() počet milisekúnd od začiatku vykonávania programu.

unsigned long teraz = millis();

Základný princíp

Namiesto príkazu „čakaj 500 ms“ používame otázku:

Uplynulo už 500 ms od poslednej činnosti?

if (teraz - predoslyCas >= interval) {
  predoslyCas = teraz;
  vykonajCinnost();
}

Ak interval ešte neuplynul, program pokračuje ďalej.

Blikanie LED bez delay()

const unsigned long INTERVAL_MS = 500;

unsigned long poslednaZmena = 0;
bool ledSvieti = false;

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
  digitalWrite(LED_BUILTIN, LOW);

  poslednaZmena = millis();
}

void loop() {
  unsigned long teraz = millis();

  if (teraz - poslednaZmena >= INTERVAL_MS) {
    poslednaZmena = teraz;
    ledSvieti = !ledSvieti;

    digitalWrite(
      LED_BUILTIN,
      ledSvieti ? HIGH : LOW
    );
  }

  // Tu môžeme kontrolovať tlačidlo alebo iné vstupy.
}

Ako program pracuje?

  1. Načíta aktuálny čas.
  2. Vypočíta čas od posledného prepnutia.
  3. Ak uplynulo aspoň 500 ms, prepne LED.
  4. Pokračuje ďalšími úlohami.

LED mení stav približne každých 500 ms, takže celá perióda je približne jedna sekunda.

Prečo používame odčítanie?

Odporúčaný zápis:

teraz - poslednaZmena >= INTERVAL_MS

Pri 32-bitovom čase sa hodnota millis() pretočí približne po 49,7 dňa.

Odčítanie neznamienkových hodnôt umožňuje správne vyhodnocovať bežné krátke intervaly aj cez toto pretočenie. Program však musí čas kontrolovať dostatočne často; týmto postupom nesledujeme ľubovoľný počet celých pretočení.

4. Viac pravidelných úloh

Čas: 18 – 23 min

Zadanie

Arduino Uno má:

  • každých 500 ms prepnúť LED,
  • každé 2 sekundy vypísať správu.

Každá úloha dostane vlastnú časovú premennú.

const unsigned long INTERVAL_LED = 500;
const unsigned long INTERVAL_VYPIS = 2000;

unsigned long casLed = 0;
unsigned long casVypis = 0;

bool ledSvieti = false;

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
  digitalWrite(LED_BUILTIN, LOW);
  Serial.begin(9600);

  unsigned long teraz = millis();
  casLed = teraz;
  casVypis = teraz;
}

void loop() {
  unsigned long teraz = millis();

  if (teraz - casLed >= INTERVAL_LED) {
    casLed = teraz;

    ledSvieti = !ledSvieti;
    digitalWrite(
      LED_BUILTIN,
      ledSvieti ? HIGH : LOW
    );
  }

  if (teraz - casVypis >= INTERVAL_VYPIS) {
    casVypis = teraz;
    Serial.println("Pravidelna sprava");
  }
}

Na jednom jadre sa tieto úlohy vykonávajú postupne. Program medzi nimi rýchlo prechádza podľa toho, ktorá má byť vykonaná.

Dva spôsoby aktualizácie času

Zápis Správanie
cas = teraz; Ďalší interval počítame od aktuálneho vykonania
cas += interval; Udržiavame plánované časové body

Druhý spôsob pomáha obmedziť posúvanie plánovaného rytmu. Pri veľkom oneskorení však musíme rozhodnúť, či zmeškané vykonania dobehneme alebo preskočíme.

Ani millis() nezaručí včasnú reakciu, ak program zablokujeme dlhou úlohou.

5. Hardvérový časovač

Čas: 23 – 27 min

Hardvérový časovač je periféria, ktorá počíta hodinové impulzy nezávisle od vykonávania hlavnej slučky.

Hodinový signál
      ↓
Delička
      ↓
Počítadlo časovača
      ↓
Pretečenie alebo porovnávacia zhoda
      ↓
Nastavenie príznaku, prerušenie alebo zmena výstupu

Základné pojmy

Hodinový signál
Zdroj impulzov pre časovač.

Delička – prescaler
Zníži frekvenciu impulzov privádzaných do počítadla.

Pretečenie – overflow
Pri bežnom počítaní nastane, keď počítadlo prekročí svoju najvyššiu hodnotu a vráti sa na začiatok.

Porovnávacia zhoda – compare match
Nastane, keď sa hodnota počítadla zhoduje s nastavenou porovnávacou hodnotou.

Počet stavov

Šírka počítadla Rozsah Počet stavov
8 bitov 0 až 255 256
16 bitov 0 až 65 535 65 536

Časovač môže napríklad:

  • pravidelne vyvolávať prerušenie,
  • generovať PWM,
  • merať čas pomocou zachytenia hodnoty počítadla,
  • počítať externé impulzy, ak to podporuje.

Nie každá činnosť časovača potrebuje ISR. Niektoré výstupy vie hardvér ovládať priamo.

6. AVR: výpočet intervalu časovača

Čas: 27 – 32 min

Arduino Uno R3 používa ATmega328P s hodinovou frekvenciou 16 MHz.

Má tri časovače:

Časovač Šírka
Timer0 8 bitov
Timer1 16 bitov
Timer2 8 bitov

V bežnom Arduino jadre pre Uno sa Timer0 používa aj na časovú základňu pre millis(), micros() a delay().

Zmena nastavenia časovača môže ovplyvniť ďalšie funkcie alebo knižnice, ktoré ho používajú.

Príklad: Timer1 v režime CTC

V režime CTC sa počítadlo po dosiahnutí nastavenej hornej hodnoty vracia na začiatok.

Pre jednoduché počítanie od 0 po hodnotu OCR1A platí:

Vzťah: T = ((OCR1A + 1) × N) / f

Kde:

  • (T) je interval porovnávacích zhôd,
  • (N) je delička,
  • (f) je frekvencia hodín časovača pred deličkou,
  • OCR1A je nastavená porovnávacia hodnota.

Výpočet intervalu 1 sekunda

Zvolíme:

  • frekvenciu (f = 16,000,000) Hz,
  • deličku (N = 1024).

Frekvencia počítania bude:

Frekvencia počítania: f = 16 000 000 / 1024 = 15 625 Hz

Na jednu sekundu potrebujeme 15 625 krokov.

Keďže počítame aj hodnotu nula:

Porovnávacia hodnota: OCR1A = 15 625 − 1 = 15 624

Výsledok: Pri tomto nastavení vzniká porovnávacia zhoda nominálne každú sekundu.

Presnosť reálneho času závisí aj od presnosti hodinového zdroja.

Prepojenie s ISR

Ak povolíme príslušné prerušenie, ISR sa môže spustiť pri každej zhode:

ISR(TIMER1_COMPA_vect) {
  // Krátka obsluha porovnávacej zhody Timer1.
}

Ide o ukážku zápisu pre AVR, nie o kompletný program. Časovač aj prerušenie by bolo potrebné najprv nakonfigurovať.

7. Časovanie na ESP32

Čas: 32 – 36 min

Pri použití Arduino frameworku môžeme na ESP32 použiť rovnaký princíp s millis().

ESP32 poskytuje aj ďalšie možnosti:

Mechanizmus Typické použitie
millis() Jednoduché pravidelné úlohy
Hardvérový časovač Časovanie pomocou periférie
esp_timer Softvérové časové služby s mikrosekundovým rozhraním
Časovanie úloh FreeRTOS Uspávanie a pravidelné vykonávanie úloh

Konkrétny počet časovačov a ich vlastnosti závisia od variantu ESP32.

Je callback vždy ISR?

Nie.

Pri esp_timer sa callbacky bežne vykonávajú v systémovej úlohe. Niektoré konfigurácie podporujú aj obsluhu v kontexte ISR.

Pravidlá pre obslužnú funkciu vyberáme podľa toho, v akom kontexte sa skutočne vykonáva.

delay() na ESP32

V Arduino frameworku pre ESP32 delay() typicky uspí volajúcu úlohu a umožní beh ďalších úloh.

Kód za delay() v tej istej úlohe však stále čaká.

Otázka pre žiakov:
Ak iné úlohy pokračujú, znamená to, že hlavná slučka už nie je blokovaná?

Odpoveď: Nie. Blokovaná je volajúca úloha, hoci ostatné úlohy môžu pracovať.

8. Raspberry Pi: časovanie v Pythone

Čas: 36 – 40 min

Raspberry Pi s Linuxom používa operačný systém, ktorý prideľuje procesorový čas viacerým procesom a vláknam.

Blokujúce čakanie

from time import sleep

while True:
    print("Pravidelna sprava")
    sleep(1)

sleep(1) pozastaví volajúce vlákno. Jeho pokračovanie sa môže oneskoriť podľa zaťaženia systému.

Navyše interval medzi výpismi zahŕňa aj čas spracovania slučky.

Plánovanie pomocou monotónnych hodín

Na meranie intervalov používame napríklad time.monotonic(). Tieto hodiny nie sú ovplyvnené bežnou zmenou systémového dátumu a času.

from time import monotonic, sleep

interval = 1.0
dalsiTermin = monotonic() + interval

while True:
    teraz = monotonic()

    if teraz >= dalsiTermin:
        print("Pravidelna sprava")

        dalsiTermin += interval

        # Pri veľkom oneskorení preskočíme zmeškané termíny.
        if dalsiTermin <= teraz:
            dalsiTermin = teraz + interval

    sleep(0.01)

Krátky sleep() obmedzuje zbytočné zaťažovanie procesora, ale zároveň pridáva oneskorenie ku kontrole termínu.

Obmedzenie Linuxu

Bežný Python program na Raspberry Pi s bežným Linuxom negarantuje presný okamih vykonania.

Pre presné krátke impulzy alebo stabilný signál je vhodné použiť podporovanú hardvérovú perifériu alebo samostatný mikrokontrolér.

9. Úloha pre žiakov

Čas: 40 – 43 min

A. Perióda blikania

LED každých 250 ms zmení svoj stav.

Otázka: Aká je celá perióda blikania a frekvencia?

Riešenie:

  • svieti 250 ms a nesvieti 250 ms,
  • perióda je 500 ms = 0,5 s,
  • frekvencia je 2 Hz.

B. Výpočet časovača

Časovač má:

  • vstupnú frekvenciu 16 MHz,
  • deličku 64,
  • v režime CTC počíta od 0 po 249.

Vypočítajte interval porovnávacích zhôd.

Výpočet: T = ((249 + 1) × 64) / 16 000 000 = 0,001 s

Výsledok: 1 ms.

C. Nájdi problém

if (millis() - poslednyCas >= 1000) {
  Serial.println("Ubehla sekunda");
}

Otázka: Čo chýba?

Odpoveď: Aktualizácia premennej poslednyCas. Po uplynutí intervalu by sa správa vypisovala pri každom ďalšom priechode slučkou.

10. Overenie vedomostí a zápis

Čas: 43 – 45 min

Otázka Odpoveď
Čo blokuje delay()? Pokračovanie volajúceho programu alebo úlohy.
Čo vracia millis()? Počet milisekúnd od začiatku vykonávania programu, s pretočením rozsahu.
Na čo slúži delička? Znižuje frekvenciu impulzov privádzaných do počítadla.
Čo je porovnávacia zhoda? Zhoda hodnoty počítadla s nastavenou porovnávacou hodnotou.
Potrebuje časovač vždy ISR? Nie.
Garantuje Python na bežnom Linuxe presné časovanie? Nie.

Zápis do zošita

Blokujúce časovanie pozastaví pokračovanie volajúceho kódu.
Neblokujúce časovanie kontroluje uplynutý čas a umožňuje vykonávať ďalšie úlohy.
Pri millis() vyhodnocujeme interval pomocou rozdielu neznamienkových časových hodnôt.
Hardvérový časovač počíta hodinové impulzy nezávisle od hlavnej slučky.
Delička znižuje frekvenciu počítania.
Časovač môže pri pretečení alebo porovnávacej zhode vyvolať prerušenie.
Presnosť časovania závisí od hodinového zdroja, použitého mechanizmu a oneskorenia spracovania.
