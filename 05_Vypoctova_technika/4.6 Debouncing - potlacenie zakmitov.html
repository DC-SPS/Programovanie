4.6 Debouncing – potlačenie zákmitov kontaktov

Prečo tlačidlo pri stlačení vytvára viac prechodov a ako ich spoľahlivo filtrovať.

Tematický celok 4Výpočtová technikaAVR · Arduino · ESP32 · Raspberry Pi45 minút

Predmet: Výpočtová technika
Ročník: tretí, stredná škola
Trvanie: 45 minút
Platformy: AVR, Arduino, ESP32 a Raspberry Pi
Nadväznosť: Prerušenia a ISR, pravidlá práce v ISR

Ciele hodiny

Po hodine má žiak vedieť:

  • vysvetliť vznik zákmitov mechanického kontaktu,
  • opísať ich vplyv na polling aj prerušenia,
  • rozlíšiť hardvérové a softvérové potlačenie zákmitov,
  • pochopiť princíp potvrdenia stabilného stavu,
  • použiť jednoduchý debounce bez blokujúceho čakania.

1. Jedno stlačenie, viac udalostí

Čas: 0 – 5 min

Predstavme si počítadlo stlačení tlačidla:

if (nastaloStlacenie) {
  pocet++;
}

Tlačidlo stlačíme raz, ale počítadlo sa zvýši napríklad o tri.

Otázka pre triedu:
Je príčinou vždy chyba programu?

Nie. Príčinou môže byť samotné mechanické tlačidlo.

Pri spojení kontaktov nevznikne vždy jedna čistá zmena signálu. Kontakty sa môžu niekoľkokrát krátko spojiť a rozpojiť.

Tento jav označujeme ako zákmit kontaktov.

Debouncing je potlačenie zákmitov tak, aby program rozpoznal jednu zamýšľanú zmenu stavu.

2. Prečo vznikajú zákmity?

Čas: 5 – 12 min

Mechanická príčina

Tlačidlo obsahuje pohyblivé kontakty. Pri stlačení do seba narazia a môžu sa krátko odraziť.

Podobný jav môže vzniknúť aj pri uvoľnení tlačidla.

Ideálny signál

Pri zapojení s INPUT_PULLUP:

HIGH ──────────┐
              │
LOW           └────────────────
              stlačenie

Reálny signál so zákmitmi

HIGH ──────────┐ ┌─┐ ┌─┐
              │ │ │ │ │
LOW           └─┘ └─┘ └─────────
              oblasť zákmitov

Procesor je dostatočne rýchly na to, aby jednotlivé zmeny zachytil.

Trvanie zákmitov závisí od typu a stavu kontaktu. Často ide o jednotky až desiatky milisekúnd. Vhodný čas filtrovania preto vyberáme podľa použitého tlačidla a požadovanej reakcie.

Dôsledky

Použitie tlačidla Možný problém
Počítadlo stlačení Jedno stlačenie zvýši počet viackrát
Prepínanie LED LED sa viackrát prepne a skončí v nečakanom stave
Pohyb v menu Kurzor preskočí viac položiek
Externé prerušenie Jedno stlačenie vyvolá viac ISR

Dve rozdielne príčiny opakovania

Opakované spracovanie nemusí spôsobovať iba zákmit.

if (digitalRead(TLACIDLO) == LOW) {
  pocet++;
}

Tento kód zvyšuje počítadlo pri každom priechode slučkou počas držania tlačidla, aj keby bol signál dokonale čistý.

Potrebujeme preto vyriešiť dve veci:

  1. Potlačiť zákmity.
  2. Rozpoznať nové stlačenie namiesto samotného držania tlačidla.

3. Ako potlačiť zákmity?

Čas: 12 – 18 min

A. Hardvérové riešenie

Používame napríklad:

  • RC filter,
  • Schmittov klopný obvod,
  • špecializovaný obvod na potlačenie zákmitov.

RC filter využíva rezistor a kondenzátor na vyhladenie krátkych zmien napätia.

Schmittov vstup má odlišný prah pre prepnutie nahor a nadol. Pomáha previesť pomaly sa meniace alebo rušené napätie na stabilný digitálny stav.

Konkrétne zapojenie a hodnoty súčiastok treba prispôsobiť vstupu mikrokontroléra. Samotný kondenzátor pripojený bez premysleného zapojenia nie je univerzálne riešenie.

B. Softvérové riešenie: potvrdenie stabilného stavu

Program prijme nový stav až vtedy, keď sa vstup určitý čas nezmení.

Príklad:

  1. Program zaznamená zmenu vstupu.
  2. Zapamätá si čas tejto zmeny.
  3. Každá ďalšia zmena začne čakanie odznova.
  4. Ak stav vydrží napríklad 30 ms, program ho prijme.
Zmena vstupu
     ↓
Zapamätaj čas
     ↓
Mení sa vstup?
  áno → začni čas merať odznova
  nie → po uplynutí intervalu prijmi stav

C. Softvérové riešenie: blokovanie ďalších udalostí

Po prijatí udalosti program určitý čas ignoruje ďalšie udalosti.

Je to jednoduché, ale neoveruje stabilitu vstupu. Môže napríklad prijať prvý rušivý impulz ako platné stlačenie.

Prečo nepoužiť iba delay()?

Blokujúce čakanie môže byť použiteľné v jednoduchej ukážke, ale počas neho hlavná slučka nevykonáva ostatné úlohy.

Na dnešnej hodine preto použijeme neblokujúce časovanie pomocou millis().

4. Arduino a AVR: jedno prepnutie LED na jedno stlačenie

Čas: 18 – 30 min

Zadanie

Každé nové stlačenie tlačidla prepne zabudovanú LED:

  • prvé stlačenie ju zapne,
  • druhé ju vypne,
  • držanie tlačidla ju neprepína opakovane.

Nový stav tlačidla prijmeme až po 30 ms bez zmeny načítanej hodnoty.

Zapojenie pre Arduino Uno R3

  • Tlačidlo medzi D2 a GND.
  • Použijeme INPUT_PULLUP.
  • LED je zabudovaná na doske.
Stav tlačidla Hodnota
Uvoľnené HIGH
Stlačené LOW

Program

const byte TLACIDLO = 2;
const unsigned long DEBOUNCE_MS = 30;

int posledneCitanie;
int stabilnyStav;

unsigned long casPoslednejZmeny = 0;
bool ledSvieti = false;

void setup() {
  pinMode(TLACIDLO, INPUT_PULLUP);
  pinMode(LED_BUILTIN, OUTPUT);

  digitalWrite(LED_BUILTIN, LOW);

  posledneCitanie = digitalRead(TLACIDLO);
  stabilnyStav = posledneCitanie;

  casPoslednejZmeny = millis();
}

void loop() {
  unsigned long teraz = millis();
  int citanie = digitalRead(TLACIDLO);

  // Každá zachytená zmena začne interval odznova.
  if (citanie != posledneCitanie) {
    posledneCitanie = citanie;
    casPoslednejZmeny = teraz;
  }

  // Nový stav prijmeme až po uplynutí intervalu.
  if (teraz - casPoslednejZmeny >= DEBOUNCE_MS) {
    if (citanie != stabilnyStav) {
      stabilnyStav = citanie;

      // Reagujeme iba na nové stlačenie.
      if (stabilnyStav == LOW) {
        ledSvieti = !ledSvieti;

        digitalWrite(
          LED_BUILTIN,
          ledSvieti ? HIGH : LOW
        );
      }
    }
  }

  // Tu môžu prebiehať ďalšie krátke úlohy.
}

Vysvetlenie premenných

Premenná Význam
citanie Aktuálne načítaná hodnota vstupu
posledneCitanie Posledná pozorovaná hodnota
stabilnyStav Už potvrdený stav tlačidla
casPoslednejZmeny Čas poslednej zachytenej zmeny
ledSvieti Aktuálny požadovaný stav LED

Krok 1: Zistíme zmenu

if (citanie != posledneCitanie) {
  posledneCitanie = citanie;
  casPoslednejZmeny = teraz;
}

Pri každej zachytenej zmene začneme interval stability merať odznova.

Krok 2: Počkáme bez zastavenia programu

if (teraz - casPoslednejZmeny >= DEBOUNCE_MS)

Program nečaká na jednom mieste. Opakovane prechádza cez loop() a kontroluje uplynutý čas.

Odčítanie časov v type unsigned long umožňuje správne vyhodnocovanie krátkych intervalov aj pri pretočení hodnoty millis().

Krok 3: Prijmeme nový stabilný stav

if (citanie != stabilnyStav) {
  stabilnyStav = citanie;
}

Ak sa potvrdený stav nemení, nová udalosť nevznikne.

Krok 4: Reagujeme iba na stlačenie

if (stabilnyStav == LOW) {
  ledSvieti = !ledSvieti;
}

Uvoľnenie tlačidla sa tiež potvrdí, ale LED neprepne.

Čo sa stane pri držaní tlačidla?

LED sa prepne iba raz. Ďalšie prepnutie vyžaduje potvrdené uvoľnenie a nové potvrdené stlačenie.

Ak je tlačidlo stlačené už pri zapnutí dosky, tento program ho prijme ako počiatočný stav. Samotné zapnutie preto LED neprepne.

Obmedzenie

Program musí vstup kontrolovať dostatočne často. Dlhé blokovanie hlavnej slučky môže spôsobiť prehliadnutie zmien.

5. ESP32 a debouncing pri prerušení

Čas: 30 – 35 min

Potrebujeme na tlačidlo prerušenie?

Pri bežnom ľudskom ovládaní často postačuje rýchly polling s neblokujúcim debouncingom.

Algoritmus z predchádzajúcej ukážky môžeme použiť aj na ESP32. Treba zvoliť vhodné GPIO a upraviť zapojenie LED podľa dosky.

Napríklad na klasickej doske ESP32 s dostupným GPIO27 môžeme tlačidlo pripojiť medzi GPIO27 a GND.

GPIO ESP32 používajú logiku 3,3 V. Dostupnosť a vlastnosti pinov overíme podľa konkrétnej dosky.

Čo ak používame prerušenie?

Prerušenie môže zachytiť aj jednotlivé zákmity.

Nevhodné riešenie:

void ARDUINO_ISR_ATTR priStlaceni() {
  delay(30);
}

Čakanie v ISR zákmit správnym spôsobom nerieši a porušuje pravidlo krátkej obsluhy.

Vhodný postup:

  1. ISR krátko oznámi, že sa vstup zmenil.
  2. Hlavný program alebo úloha začne sledovať stav.
  3. Ďalšie spracovanie potvrdí stabilný stav mimo ISR.

Oznámenie medzi ISR a hlavným programom musí byť bezpečne synchronizované, ako sme ukázali v predchádzajúcej hodine.

Dôležitý detail

Pri metóde potvrdenia stability nestačí zistiť iba prvú zostupnú hranu a o 30 ms vstup raz prečítať.

Takéto riešenie overí stav v jednom neskoršom okamihu, ale nedokazuje, že bol celý interval stabilný.

Pre skutočné potvrdenie stability musíme sledovať aj ďalšie zmeny, napríklad pollingom mimo ISR alebo vhodným mechanizmom zaznamenávania oboch hrán.

6. Raspberry Pi: parameter bounce_time

Čas: 35 – 39 min

Na Raspberry Pi s Linuxom môžeme použiť Python a knižnicu gpiozero.

Zapojenie

  • Tlačidlo medzi GPIO17 a GND.
  • GPIO17 je na bežnom 40-pinovom konektore fyzický pin 11.
  • Číslovanie v programe je BCM GPIO.

Program

from gpiozero import Button
from signal import pause

pocet = 0

def pri_stlaceni():
    global pocet
    pocet += 1
    print(f"Pocet stlaceni: {pocet}")

tlacidlo = Button(
    17,
    pull_up=True,
    bounce_time=0.05
)

tlacidlo.when_pressed = pri_stlaceni

try:
    pause()
finally:
    tlacidlo.close()

Vysvetlenie

bounce_time=0.05

Hodnota je uvedená v sekundách:

0,05 s = 50 ms

Parameter zapína potlačenie zákmitov poskytované knižnicou a použitým GPIO backendom. Dokumentované správanie spočíva v ignorovaní ďalších zmien počas nastaveného intervalu po zmene.

Nejde automaticky o rovnaký algoritmus potvrdenia stability, aký sme naprogramovali na Arduine.

Výber intervalu

  • Príliš krátky interval nemusí potlačiť všetky zákmity.
  • Príliš dlhý interval môže potlačiť aj rýchle platné ovládanie.
  • Výsledok treba overiť na konkrétnom tlačidle.

Python callback je používateľská funkcia spúšťaná cez knižnicu, nie mikrokontrolérová ISR.

GPIO Raspberry Pi používajú logiku 3,3 V a nesmú dostať priamo 5 V.

7. Úloha pre žiakov

Čas: 39 – 43 min

A. Vyhodnoť priebeh

Používame potvrdenie stability s intervalom 30 ms. Počiatočný potvrdený stav je HIGH.

Predpokladajme, že program zachytí všetky uvedené zmeny.

Čas Nový stav vstupu
100 ms LOW
103 ms HIGH
107 ms LOW
110 ms HIGH
114 ms LOW
Ďalej Zostáva LOW

Otázky:

  1. Kedy nastala posledná zmena?
  2. Kedy môže program najskôr potvrdiť stlačenie?
  3. Koľkokrát má prepnúť LED?

Odpovede:

  1. V čase 114 ms.
  2. Pri prvej kontrole v čase 144 ms alebo neskôr, ak sa vstup nezmení.
  3. Raz.

B. Nájdi problém

if (digitalRead(TLACIDLO) == LOW) {
  pocet++;
  delay(30);
}

Otázka: Zabezpečuje tento program jedno zvýšenie počítadla na jedno stlačenie?

Odpoveď: Nie. Pri dlhšom držaní tlačidla bude počítadlo opakovane zvyšovať. Nerozpoznáva nové stlačenie a blokuje hlavnú slučku.

C. Upravte program

Upravte ukážku pre Arduino tak, aby namiesto prepínania LED vypísala poradové číslo potvrdeného stlačenia.

Pokyn: počítadlo zvýš v mieste, kde program prijme nový stabilný stav LOW.

8. Overenie vedomostí a zápis

Čas: 43 – 45 min

Rýchle otázky

Otázka Odpoveď
Čo spôsobuje zákmity? Mechanické odrazy kontaktov pri zmene stavu.
Vznikajú iba pri stlačení? Nie, môžu vzniknúť aj pri uvoľnení.
Odstráni ich INPUT_PULLUP? Nie, zabezpečuje definovanú úroveň rozpojeného vstupu.
Odstráni ich použitie prerušenia? Nie, prerušenie môže zachytiť viac hrán.
Čo znamená potvrdenie stability? Prijatie nového stavu až po stanovenom čase bez zachytenej zmeny.
Patrí delay() na potlačenie zákmitov do ISR? Nie.

Zápis do zošita

Zákmity kontaktov sú krátke opakované zmeny signálu pri stlačení alebo uvoľnení mechanického tlačidla.
Debouncing potláča zákmity, aby zariadenie správne rozpoznalo zamýšľanú zmenu.
Hardvérové riešenia využívajú napríklad RC filter a Schmittov obvod.
Softvérové riešenie môže prijať nový stav až po intervale stability.
Potlačenie zákmitov a rozpoznanie nového stlačenia sú dve odlišné úlohy.
Pri neblokujúcom riešení môže hlavný program počas filtrovania vykonávať ďalšie činnosti.
