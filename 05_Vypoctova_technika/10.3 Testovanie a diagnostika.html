10.3 Testovanie a diagnostika

Návrh a realizácia embedded systému · 45 minút

Simulácia: Ukážky C++ možno preniesť do Wokwi ESP32. Skúšobný program vypíše výsledky testov do sériového monitora. Simulátor overí logiku a kompiláciu, nie skutočný snímač, ovládač ventilátora ani napájací zdroj. V reálnom zapojení používajte vhodný nízkonapäťový ventilátor a ovládač.

Trvanie: 45 minút Nadväznosť: Požiadavky a architektúra.

Ciele hodiny

Žiak má vedieť:

  • rozlíšiť testovanie a diagnostiku,
  • zostaviť testovací prípad,
  • otestovať bežné, hraničné a poruchové stavy,
  • systematicky hľadať príčinu chyby,
  • zaznamenať výsledok testu.

1. Testovanie a diagnostika

0 – 5 min

Testovanie overuje správanie systému oproti očakávaniu.

Diagnostika zisťuje príčinu nesprávneho správania.

Veta „raz to fungovalo“ nie je dostatočný dôkaz splnenia požiadaviek.

2. Čo a ako testujeme?

5 – 15 min

ÚroveňPríklad
Samostatná funkciaVýpočet regulačného rozhodnutia
ModulČítanie snímača a overenie platnosti
IntegráciaMeranie ovláda správny výstup
Celý systémPrevádzka vrátane porúch a reštartu

Testovací prípad

Obsahuje:

  • identifikátor,
  • overovanú požiadavku,
  • počiatočný stav,
  • vstup alebo postup,
  • očakávaný výsledok,
  • skutočný výsledok,
  • hodnotenie.

Typy skúšok

  • bežný stav,
  • hraničná hodnota,
  • neplatný vstup,
  • výpadok periférie,
  • výpadok siete,
  • reštart,
  • dlhšia prevádzka.

3. Testovanie hysterézie

15 – 27 min

Regulácia:

  • zapnúť pri teplote ≥ 28 °C,
  • vypnúť pri teplote ≤ 26 °C,
  • medzi prahmi zachovať stav.

Samostatná funkcia v C++

Platforma: cpp

bool rozhodniVentilator(
    float teplota,
    bool aktualneZapnuty
) {
    if (teplota >= 28.0f) {
        return true;
    }

    if (teplota <= 26.0f) {
        return false;
    }

    return aktualneZapnuty;
}

struct TestovaciPripad {
    float teplota;
    bool povodnyStav;
    bool ocakavanyStav;
};

const TestovaciPripad testy[] = {
    {25.0f, false, false},
    {28.0f, false, true},
    {27.0f, true, true},
    {27.0f, false, false},
    {26.0f, true, false},
    {30.0f, false, true}
};

void setup() {
    Serial.begin(115200);

    const unsigned int pocetTestov = sizeof(testy) / sizeof(testy[0]);
    for (unsigned int i = 0; i < pocetTestov; ++i) {
        const bool skutocnyStav = rozhodniVentilator(
            testy[i].teplota,
            testy[i].povodnyStav
        );

        Serial.print("T");
        Serial.print(i + 1);
        Serial.println(skutocnyStav == testy[i].ocakavanyStav ? " - OK" : " - CHYBA");
    }
}

void loop() {
}
Otvoriť Wokwi ESP32

Funkcia predpokladá platnú konečnú teplotu. Kontrola platnosti a poruchový stav sa riešia pred jej použitím.

Poruchový test

Postup: Počas prevádzky zastavíme prísun platných meraní.

Očakávanie: Po prekročení trojsekundového limitu sa zobrazí porucha a aktivuje definovaný výstup.

Presnú reakciu hodnotíme podľa požiadavky, nie podľa domnienky testujúceho.

4. Systematická diagnostika

27 – 36 min

Príklad: ventilátor sa nezapína.

Postupujeme po reťazci:

  1. Je napájanie správne?
  2. Je snímač dostupný?
  3. Je načítaná teplota platná?
  4. Vyhodnotila logika požiadavku na zapnutie?
  5. Zmenil sa GPIO signál?
  6. Reaguje ovládač?
  7. Je záťaž správne pripojená?

Nástroje

NástrojPoužitie
Sériový logStav programu a hodnoty
MultimeterNapätie, odpor, kontinuita
Logický analyzátorDigitálne priebehy a protokoly
OsciloskopPriebeh napätia v čase
DebuggerZastavenie programu a kontrola premenných

Pravidlá merania

  • Odpor a kontinuitu meriame na odpojenom obvode.
  • Pri meraní prúdu sa multimeter pripája inak než pri meraní napätia.
  • Zem osciloskopu môže byť spojená s ochrannou zemou; pripájame ju iba na vhodný bod podľa zapojenia.
  • Meníme jednu vec naraz a zapisujeme výsledok.

5. Samostatná úloha

36 – 41 min

Navrhnitete päť testov vlastného projektu:

  • dva bežné,
  • jeden hraničný,
  • jeden poruchový,
  • jeden po reštarte.

Ku každému zapíš očakávaný výsledok.

6. Zápis

41 – 45 min

Testovanie porovnáva skutočné a očakávané správanie.

Diagnostika hľadá príčinu chyby.

Testujeme aj hranice, poruchy a reštart.

Test musí mať definovaný postup a očakávanie.

Pri hľadaní chyby postupujeme systematicky od napájania cez vstupy a logiku k výstupom.

Výstup hodiny: testovací plán a záznam výsledkov.
