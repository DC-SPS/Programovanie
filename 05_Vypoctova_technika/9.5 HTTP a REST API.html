1. HTTP

0 – 17 min

HTTP je aplikačný protokol založený na výmene požiadaviek a odpovedí.

Klient môže byť:

  • prehliadač,
  • ESP32,
  • Python program.

Server spracuje požiadavku a odošle odpoveď.

Požiadavka obsahuje

  • metódu,
  • cieľovú cestu,
  • hlavičky,
  • podľa potreby telo.

2. REST API

17 – 27 min

REST je architektonický štýl. Nie každé HTTP rozhranie s JSON je plne REST.

Pre úvod používame zdroje:

Platforma: text

/api/devices
/api/devices/ucebna01
/api/measurements

Príklad merania:

Platforma: json

{
  "device_id": "ucebna01",
  "temperature_c": 23.6,
  "valid": true
}
?pecifik?cia MQTT

API musí určiť povinné polia, typy, jednotky a reakcie na chyby.

HTTP a HTTPS

HTTPS používa TLS na ochranu spojenia.

Klient má overovať certifikát servera a jeho názov. Vypnutie overovania certifikátu odstraňuje dôležitú časť ochrany.

HTTP/1.1 a HTTP/2 bežne používajú TCP; HTTP/3 používa QUIC nad UDP.

import requests

url = "http://192.168.1.50:8000/api/measurements"

meranie = {
    "device_id": "ucebna01",
    "temperature_c": 23.6

4. Timeout a opakovanie

37 – 41 min

Ak klient nedostane odpoveď, nemusí vedieť, či server požiadavku vykonal.

Opakovaný POST môže vytvoriť duplicitnú položku. Pomôcť môže:

  • jednoznačné ID merania,
  • kontrola duplicít,
  • idempotentný návrh operácie.

5. Zápis

41 – 45 min

HTTP používa požiadavky a odpovede.

Metóda vyjadruje typ operácie, stavový kód výsledok spracovania.

JSON je dátový formát, nie transportný protokol.

REST je architektonický štýl práce so zdrojmi.

HTTPS chráni spojenie pomocou TLS.

Klient musí riešiť timeouty, chyby a možné duplicity.
