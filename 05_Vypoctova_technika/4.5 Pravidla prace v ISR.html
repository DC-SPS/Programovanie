1. Opakovanie: Čo sa deje počas ISR?

Čas: 0 – 5 min

ISR je obslužná rutina prerušenia. Procesor ju vykonáva pri obsluhe príslušnej požiadavky.

Na jednojadrovom AVR je počas ISR hlavný program pozastavený. Pri bežnej obsluhe sú zároveň globálne prerušenia zakázané, takže ďalšie ISR čakajú.

Motivačný príklad

Mikrokontrolér:

  • prijíma údaje cez sériovú linku,
  • počíta impulzy,
  • ovláda displej.

Po stlačení tlačidla spustí ISR, ktorá čaká jednu sekundu.

Otázka pre žiakov:
Čo môže počas tejto sekundy prestať správne fungovať?

Očakávané odpovede: hlavný program, spracovanie komunikácie, časovanie alebo počítanie impulzov.

Hardvér môže niektoré udalosti dočasne zaznamenať, ale jeho pamäť je obmedzená. Opakované udalosti sa môžu zlúčiť do jednej požiadavky alebo sa môžu stratiť údaje.

Základná myšlienka hodiny: ISR udalosť rýchlo zachytí a rozsiahlejšiu prácu odovzdá ďalej.

2. Základné pravidlá práce v ISR

Čas: 5 – 13 min

Pravidlo 1: ISR má byť krátka a predvídateľná

Vhodné činnosti:

  • nastaviť príznak,
  • zvýšiť počítadlo,
  • prevziať údaj z periférie, ak to jej obsluha vyžaduje,
  • vykonať krátku, nevyhnutnú reakciu.
void priImpulze() {
  pocetImpulzov++;
}

Nevhodné činnosti:

  • dlhé výpočty,
  • čakanie na používateľa,
  • rozsiahle spracovanie údajov,
  • dlhé alebo časovo nepredvídateľné slučky.

Krátka ISR zmenšuje oneskorenie hlavného programu aj ďalších obslúh.

Pravidlo 2: V ISR nečakáme pomocou delay()

Nevhodný príklad:

void priStlaceni() {
  delay(500);
}

Na klasickom Arduino Uno sa časovanie delay() opiera o mechanizmy, ktoré počas bežnej ISR nefungujú ako v hlavnom programe. Funkcia preto nemusí správne dokončiť čakanie.

Aj aktívne čakanie by zbytočne zadržiavalo procesor v ISR.

Ak treba niečo vykonať neskôr, ISR zaznamená požiadavku a časovanie zabezpečí hlavný program.

Pravidlo 3: Výpisy a komunikáciu presunieme mimo ISR

Nevhodný príklad:

void priStlaceni() {
  Serial.println("Tlacidlo bolo stlacene");
}

Sériový výpis používa vyrovnávaciu pamäť a jeho správanie závisí od platformy. V ISR môže výrazne zdržiavať alebo viesť k zablokovaniu.

Podobne do bežnej ISR nepatrí:

  • posielanie HTTP požiadavky,
  • pripájanie k Wi-Fi,
  • zápis do súboru,
  • aktualizácia celého displeja.

Používame iba funkcie, pri ktorých platforma výslovne povoľuje volanie z ISR.

Pravidlo 4: Vyhýbame sa dynamickému prideľovaniu pamäte

V ISR nevytvárame rozsiahle objekty ani texty pomocou operácií ako:

String sprava = "Nova udalost";

Dynamické prideľovanie pamäte môže používať zámky a mať nepredvídateľný čas vykonania.

3. Zdieľané údaje a význam volatile

Čas: 13 – 20 min

ISR potrebuje hlavnému programu oznámiť, že nastala udalosť. Použijeme spoločnú premennú:

volatile bool udalost = false;

void priStlaceni() {
  udalost = true;
}

Čo znamená volatile?

volatile upozorňuje prekladač, že premenná sa môže meniť spôsobom, ktorý z bežného toku programu nevidí — napríklad v ISR.

Pri príslušných prístupoch preto musí zabezpečiť skutočné čítanie alebo zápis a nemôže sa spoliehať iba na skôr zapamätanú hodnotu.

Čo volatile nezabezpečuje?

volatile nezaručuje atómovosť ani vzájomné vylúčenie.

Nezabezpečí, aby:

  • viac krokov prebehlo ako jeden nedeliteľný celok,
  • dve vykonávania súčasne nemenili spoločné údaje,
  • sa automaticky vyriešila synchronizácia medzi jadrami ESP32.

Atómová operácia

Atómová operácia je z pohľadu ostatných vykonávaní nedeliteľná.

ATmega328P je 8-bitový mikrokontrolér. Bežné načítanie 16-bitovej premennej vyžaduje viac krokov.

volatile uint16_t pocet = 0;

Ak ISR zmení premennú medzi načítaním jej jednotlivých bajtov, hlavný program môže dostať nesprávne zloženú hodnotu.

Strata udalosti aj pri bool

Problematický kód:

if (udalost) {
  spracujUdalost();
  udalost = false;
}

Možný priebeh:

  1. Hlavný program zistí true.
  2. Spustí spracovanie.
  3. Príde ďalšie prerušenie a nastaví true.
  4. Hlavný program dokončí spracovanie a zapíše false.
  5. Nová udalosť sa stratí.

Riešením je bezpečne prevziať a vymazať príznak ešte pred spracovaním.

4. AVR a Arduino: bezpečné prevzatie udalosti

Čas: 20 – 27 min

Zadanie

Po stlačení tlačidla Arduino Uno vypíše správu. ISR iba nastaví príznak a výpis vykoná hlavný program.

Zapojenie

  • Tlačidlo medzi D2 a GND.
  • Vstup použije INPUT_PULLUP.
  • Stlačenie vyvolá hranu FALLING.

Program pre Arduino Uno R3

#include <util/atomic.h>

const byte TLACIDLO = 2;
volatile bool udalost = false;

void priStlaceni() {
  udalost = true;
}

void setup() {
  Serial.begin(9600);
  pinMode(TLACIDLO, INPUT_PULLUP);

  attachInterrupt(
    digitalPinToInterrupt(TLACIDLO),
    priStlaceni,
    FALLING
  );
}

void loop() {
  bool spracovat;

  ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
    spracovat = udalost;
    udalost = false;
  }

  if (spracovat) {
    Serial.println("Bola zachytena udalost.");
  }
}

Ako funguje chránený blok?

ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
  spracovat = udalost;
  udalost = false;
}

Na AVR počas týchto dvoch operácií dočasne zakáže prerušenia. ISR preto nemôže vstúpiť medzi prevzatie a vymazanie príznaku.

Po skončení obnoví predchádzajúci stav povolenia prerušení.

Tento mechanizmus je určený pre AVR; nejde o univerzálny kód pre všetky dosky Arduino.

Čo ak udalosť príde počas výpisu?

ISR nastaví príznak znova. Hlavný program ho prevezme pri ďalšom priechode slučkou.

Výpis je mimo chráneného bloku, preto nepredlžuje čas zákazu prerušení.

Obmedzenie príznaku

Ak pred prevzatím príznaku príde viac udalostí, výsledkom bude stále iba hodnota true.

Príznak teda znamená:

Nastala aspoň jedna udalosť.

Neznamená počet udalostí. Navyše mechanické tlačidlo môže vytvoriť viac udalostí v dôsledku zákmitov. Ich potlačeniu sa bude venovať nasledujúca hodina.

5. Keď potrebujeme počítať impulzy

Čas: 27 – 30 min

Pri snímači otáčok môžeme potrebovať počet zachytených impulzov.

#include <util/atomic.h>

volatile uint16_t pocetImpulzov = 0;

void priImpulze() {
  pocetImpulzov++;
}

Hlavný program bezpečne prevezme počet a vynuluje počítadlo:

uint16_t prevzatyPocet;

ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
  prevzatyPocet = pocetImpulzov;
  pocetImpulzov = 0;
}

// Spracovanie prebehne až mimo chráneného bloku.

Prečo chránime oba kroky?

Potrebujeme zabrániť:

  • načítaniu neúplnej 16-bitovej hodnoty,
  • strate zvýšenia počítadla medzi prevzatím a vynulovaním.

Ani počítadlo nezaručuje zachytenie ľubovoľne rýchlych impulzov. Procesor musí stíhať obsluhu a premenná nesmie pretiecť. Pre vysoké frekvencie môže byť vhodnejšie hardvérové počítadlo.

6. ESP32: kritická sekcia

Čas: 30 – 35 min

Niektoré varianty ESP32 majú viac procesorových jadier. Samotné zakázanie prerušení na jednom jadre nezastaví druhé jadro.

Na ochranu spoločných údajov preto použijeme mechanizmus kritickej sekcie poskytovaný platformou.

Ukážka pre Arduino framework na ESP32

Príklad predpokladá dosku s dostupným GPIO27. Tlačidlo je pripojené medzi GPIO27 a GND.

const int TLACIDLO = 27;

portMUX_TYPE zamok = portMUX_INITIALIZER_UNLOCKED;
volatile bool udalost = false;

void ARDUINO_ISR_ATTR priStlaceni() {
  portENTER_CRITICAL_ISR(&zamok);
  udalost = true;
  portEXIT_CRITICAL_ISR(&zamok);
}

void setup() {
  Serial.begin(115200);
  pinMode(TLACIDLO, INPUT_PULLUP);

  attachInterrupt(
    digitalPinToInterrupt(TLACIDLO),
    priStlaceni,
    FALLING
  );
}

void loop() {
  bool spracovat;

  portENTER_CRITICAL(&zamok);
  spracovat = udalost;
  udalost = false;
  portEXIT_CRITICAL(&zamok);

  if (spracovat) {
    Serial.println("Bola zachytena udalost.");
  }
}

Čo si zapamätať?

  • ISR aj hlavný program používajú rovnaký zámok.
  • Vo vnútri chránenej časti je iba krátky prístup k údajom.
  • Výpis zostáva mimo kritickej sekcie.
  • ISR používa variant funkcií s príponou _ISR.

Vo väčších aplikáciách sa udalosti odovzdávajú aj cez fronty alebo notifikácie FreeRTOS. Z ISR sa pritom používajú funkcie určené na tento účel, často označené FromISR.

GPIO ESP32 používajú logiku 3,3 V.

7. Raspberry Pi: pravidlá pre callback

Čas: 35 – 39 min

Na Raspberry Pi s Linuxom nie je Python callback knižnice gpiozero priamou hardvérovou ISR.

Aj callback však potrebuje rozumnú organizáciu práce. Ak v ňom vykonávame dlhú operáciu, môžeme zdržiavať spracovanie ďalších udalostí.

Odovzdanie udalosti pomocou Event

from gpiozero import Button
from threading import Event

udalost = Event()

def pri_stlaceni():
    udalost.set()

tlacidlo = Button(
    17,
    pull_up=True,
    bounce_time=0.05
)

tlacidlo.when_pressed = pri_stlaceni

try:
    while True:
        udalost.wait()
        udalost.clear()

        print("Spracuvam udalost v hlavnom programe.")

finally:
    tlacidlo.close()

Vysvetlenie

  • Callback iba nastaví objekt Event.
  • wait() čaká bez neustálej kontroly v slučke.
  • Hlavný program vykoná spracovanie.
  • Event je mechanizmus vhodný na signalizáciu medzi vláknami.

Podobne ako príznak bool, aj Event môže viac oznámení zlúčiť do jedného. Nie je počítadlom ani frontou. Ak potrebujeme uchovať jednotlivé položky udalostí, použijeme napríklad queue.Queue.

Rozdiel oproti AVR: print() môže byť v Python callbacku dovolený, ale v mikrokontrolérovej ISR sa riadime oveľa prísnejšími obmedzeniami.

8. Úloha: Nájdi a oprav chyby

Čas: 39 – 43 min

Nasledujúca funkcia má na Arduino Uno obsluhovať stlačenie tlačidla:

void priStlaceni() {
  Serial.println("Stlacene");

  delay(1000);

  while (digitalRead(2) == LOW) {
    // Cakanie na uvolnenie tlacidla.
  }
}

Otázky

  1. Ktoré operácie sú nevhodné?
  2. Čo sa stane, ak používateľ drží tlačidlo dlho?
  3. Ako by mala ISR vyzerať?
  4. Kde vykonáme výpis a prípadné časovanie?

Riešenie pre učiteľa

Nevhodné sú:

  • sériový výpis v ISR,
  • delay(1000),
  • čakanie na uvoľnenie tlačidla v slučke.

Dlhé držanie tlačidla môže udržiavať procesor v ISR. Na Uno navyše nemožno očakávať správne fungovanie uvedeného delay().

Opravená ISR:

volatile bool udalost = false;

void priStlaceni() {
  udalost = true;
}

Hlavný program bezpečne prevezme príznak a vykoná výpis. Čakanie na uvoľnenie alebo časovanie rieši mimo ISR, ideálne bez blokovania ostatných činností.

9. Overenie vedomostí a zápis

Čas: 43 – 45 min

Rýchle otázky

Otázka Odpoveď
Prečo má byť ISR krátka? Aby čo najmenej zdržiavala hlavný program a ďalšie obsluhy.
Zaručuje volatile atómovosť? Nie.
Môže príznak bool spočítať päť udalostí? Nie, zaznamená iba to, že nastala aspoň jedna.
Kam patrí bežný sériový výpis? Do hlavného programu alebo vhodnej úlohy.
Má byť kritická sekcia dlhá? Nie, má chrániť iba nevyhnutné krátke operácie.

Zápis do zošita

ISR má byť krátka a predvídateľná.
Dlhé výpočty, čakanie a bežnú komunikáciu vykonávame mimo ISR.
ISR môže nastaviť príznak alebo zvýšiť počítadlo.
volatile upozorňuje prekladač na možné zmeny premennej, ale nezabezpečuje atómovosť ani synchronizáciu.
Spoločné údaje podľa potreby chránime krátkou kritickou sekciou.
Príznak zaznamenáva výskyt udalosti; počítadlo zaznamenáva počet obslúžených udalostí.
