2.1 Von Neumannova a Harvardova architektúra

Architektúra mikrokontroléra · 45 minút

Trvanie: 45 minút Pomôcky: tabuľa, kartičky „inštrukcia“, „údaj“, „CPU“ a „pamäť“.

Ciele hodiny

Žiak má vedieť:

  • vysvetliť úlohu procesora, pamäte a zberníc,
  • rozlíšiť von Neumannovu a harvardskú architektúru,
  • opísať ich základné výhody a obmedzenia,
  • vysvetliť pojem modifikovaná harvardská architektúra,
  • zaradiť AVR a moderné procesory bez neprimeraného zjednodušovania.

1. Program a údaje

0 – 5 min

Procesor potrebuje počas práce získavať:

  • inštrukcie – čo má vykonať,
  • údaje – s čím má pracovať.

Príklad:

vysledok = teplota + 2;

Procesor vykoná inštrukcie na získanie hodnoty, sčítanie a uloženie výsledku.

Architektúra určuje aj to, ako sú procesor, programová pamäť a dátová pamäť prepojené.

Otázka pre triedu: Je inštrukcia „sčítaj“ to isté ako číslo, ktoré sčítavame?

*Odpoveď: Nie. Inštrukcia určuje činnosť, údaj je jej vstupom alebo výsledkom.*

2. Základné bloky

Druhy prenášaných informácií

  • Adresa: určuje vybrané miesto alebo zariadenie.
  • Dáta: predstavujú prenášaný obsah.
  • Riadenie: určuje napríklad čítanie alebo zápis.

Zbernica nemusí mať pri každom type systému jednoduchú podobu skupiny viditeľných vodičov. Ide aj o vnútorné prepojenia čipu.

3. Von Neumannova architektúra

13 – 23 min

V základnom modeli majú program a údaje spoločný pamäťový priestor a spoločnú cestu prístupu z CPU.

             ┌─────────────────┐
             │       CPU       │
             └────────┬────────┘
                      │
              spoločná cesta
                      │
             ┌────────┴────────┐
             │     Pamäť       │
             │ program + údaje │
             └─────────────────┘

Výhody

  • Jednotný adresový priestor.
  • Rovnaký základný mechanizmus prístupu k programu a údajom.
  • Flexibilné využitie pamäťového priestoru.

Obmedzenie

Načítanie inštrukcie a prístup k údajom môžu súperiť o spoločnú prenosovú cestu.

Toto obmedzenie sa označuje ako von Neumannovo úzke hrdlo.

Neznamená to, že každý moderný procesor musí pri každej inštrukcii jednoducho striedať jeden prenos programu a jeden prenos údajov. Cache a ďalšie mechanizmy situáciu výrazne menia.

Aktivita

Jeden žiak predstavuje CPU a druhý pamäť. Kartičky s inštrukciami a údajmi odovzdávajú cez jednu „bránu“.

Trieda sleduje, ako spoločná cesta obmedzuje súčasný prenos.

4. Harvardova architektúra

23 – 33 min

V základnom modeli sú program a údaje uložené v oddelených pamäťových priestoroch, ku ktorým vedú samostatné cesty.

┌────────────────┐       ┌────────────────┐
│ Pamäť programu │       │ Pamäť údajov   │
└───────┬────────┘       └────────┬───────┘
        │                        │
        └──────────┐  ┌──────────┘
                   │  │
                ┌──┴──┴──┐
                │  CPU   │
                └────────┘

Výhody

  • Možnosť súčasne získavať inštrukciu a pristupovať k údajom.
  • Programová a dátová pamäť môžu mať rozdielne vlastnosti.
  • Môžu používať rozdielnu šírku slova alebo spôsob adresovania.

Obmedzenia

  • Prístup k programovým údajom môže vyžadovať osobitné inštrukcie.
  • Pamäťové priestory sa nepoužívajú vždy rovnakým spôsobom.
  • Organizácia môže byť pre programátora zložitejšia.

AVR ako príklad

ATmega328P používa harvardské usporiadanie:

  • program je vo Flash,
  • pracovné údaje sú v dátovom priestore vrátane SRAM,
  • programový a dátový priestor sú oddelené.

Procesor však dokáže pomocou príslušných mechanizmov čítať aj údaje uložené vo Flash.

5. Moderné riešenia

33 – 40 min

Modifikovaná harvardská architektúra

Moderné procesory často kombinujú vlastnosti oboch prístupov:

  • oddelené cesty alebo cache pre inštrukcie a dáta,
  • spoločnú hlavnú pamäť alebo jednotný pohľad na adresy.

Preto nemožno všetky procesory označiť iba podľa toho, či fyzicky obsahujú jednu RAM.

Porovnanie

VlastnosťVon Neumannov modelHarvardský model
Programový a dátový priestorSpoločnýOddelený
Prístupové cestySpoločnáSamostatné
Súčasný prístup k inštrukcii a dátamObmedzený spoločnou cestouUmožnený oddelenými cestami
Práca s programovou pamäťouJednotnejšiaMôže vyžadovať osobitný prístup

Procesory ARM používané v Raspberry Pi majú podľa konkrétneho jadra zložitejšiu pamäťovú hierarchiu, často s oddelenými inštrukčnými a dátovými cache.

Ani ESP32 nemá jeden univerzálny jednoduchý model pre všetky varianty. Rozlišujeme konkrétny čip a jeho pamäťovú organizáciu.

6. Overenie a zápis

40 – 45 min

Pamäťový priestor programu a údajov a základná cesta prístupu.

  1. Čo je spoločné vo von Neumannovom modeli?

Programovú a dátovú pamäť aj prístupové cesty.

  1. Čo oddeľuje harvardský model?

Nie. Môže na to poskytovať osobitné mechanizmy.

  1. Znamená Harvardova architektúra nemožnosť čítať konštanty z Flash?

Zápis do zošita

Von Neumannova architektúra používa spoločný priestor programu a údajov.

Harvardova architektúra oddeľuje programový a dátový priestor.

Oddelené cesty umožňujú súčasný prístup k inštrukciám a údajom.

AVR je príklad harvardského usporiadania.

Moderné procesory často kombinujú vlastnosti oboch prístupov.

Praktická ukážka: čítanie vstupu a riadenie LED

Úplný program skopírujte do online simulátora Arduino Uno. Simulátor predstavuje mikrokontrolér ATmega328P a umožňuje sledovať vykonávanie programu. Zapojte tlačidlo medzi pin 2 a GND.

Otvoriť online simulátor Arduino Uno (Wokwi)
const byte LED_PIN = LED_BUILTIN;
const byte INPUT_PIN = 2;
volatile bool inputChanged = false;

void onInputChange() {
    inputChanged = true;
}

void setup() {
    pinMode(LED_PIN, OUTPUT);
    pinMode(INPUT_PIN, INPUT_PULLUP);
    attachInterrupt(digitalPinToInterrupt(INPUT_PIN), onInputChange, FALLING);
}

void loop() {
    if (inputChanged) {
        noInterrupts();
        inputChanged = false;
        interrupts();
        digitalWrite(LED_PIN, !digitalRead(LED_PIN));
    }
}
