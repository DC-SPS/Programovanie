18 git reset a git checkout

Informatika s Mišom · verzovanie kódu

Cieľ prednášky

Rozlíšite vrátenie stagingu, reset vetvy a bezpečné obnovenie súboru.

Teoretický základ a koncepty

`git reset` môže presunúť HEAD a meniť staging alebo pracovné súbory. `--soft` ponechá zmeny pripravené, predvolený `--mixed` ich ponechá v pracovnom strome a `--hard` prepíše staging aj pracovný strom. `git checkout` je starší viacúčelový príkaz; na prepínanie použite `switch`, na obnovu súboru `restore`. Pre zdieľané commity je bezpečnejšie `git revert`.

Praktické príkazy

ÚčelPríkaz
Zrušte staging bez straty úprav
git restore --staged subor.txt
Obnovte súbor z posledného commitu (zahodí jeho úpravy)
git restore subor.txt
Vráťte posledný commit, zmeny ponechajte pripravené
git reset --soft HEAD~1
Bezpečne vráťte zdieľaný commit novým commitom
git revert HEAD
Starý spôsob prepnutia vetvy
git checkout main

Samostatná úloha

Vytvorte skúšobný commit, pridajte ďalšiu úpravu do stagingu a použite `git restore --staged`. Ukážte, že úprava zostala v pracovnom strome.
