Udalostne riadený program

Program čaká na udalosti a reaguje podľa toho, čo používateľ urobí

4. ročník SPŠ · C++ príprava pre Win32

Bežná konzolová úloha často vykoná príkazy v pevnom poradí. Desktopová aplikácia väčšinu času čaká: používateľ klikne, stlačí kláves alebo zavrie okno. Program spracuje doručenú udalosť, vykoná príslušnú reakciu a opäť čaká.

Čakaj → rozpoznaj → reaguj → čakaj znova
Začiatok hodiny: skontroluj pracovisko a počítač; závadu ihneď oznám vyučujúcemu. Poškodené alebo nebezpečné zariadenie nepoužívaj. Stručný súhrn pošli cez EduPage podľa pokynov.

Ciele hodiny

Na konci hodiny dokážeš:

  • vysvetliť rozdiel medzi pevným postupom príkazov a tokom riadeným udalosťami;
  • opísať základné kroky cyklu udalostí;
  • priradiť používateľskú akciu k udalosti a vhodnej reakcii;
  • vysvetliť, prečo konzolová simulácia nie je skutočná Windows správová slučka.

Prepojenie s hodinou 9

Už poznáme metódy a obsluhu udalostí. Metóda je operácia, ktorú program môže zavolať. Udalostne riadený program čaká na udalosti a až podľa nich rozhoduje, ktorú obsluhu alebo metódu vykoná.

Tok riadenia

1 · Čakajna ďalšiu udalosť
2 · Prijmiudalosť / správu
3 · Rozhodniktorá akcia nastala
4 · Reagujzmeň stav a pokračuj

Cyklus sa opakuje, kým aplikácia nedostane udalosť, ktorá znamená ukončenie. V GUI môže systém doručovať kliknutia a správy oknu. Konkrétnu Win32 správovú slučku a `WndProc` preberieme až pri tvorbe Windows aplikácie.

Pevný postup príkazov

  1. Program začne vykonávanie.
  2. Vykoná prvý príkaz.
  3. Pokračuje ďalšími príkazmi v určenom poradí.
  4. Po poslednom príkaze skončí.

Vhodné napríklad pre výpočet alebo krátku dávkovú úlohu.

Udalostne riadený tok

  1. Program pripraví svoj stav a obsluhy.
  2. Čaká na používateľskú alebo systémovú udalosť.
  3. Rozpozná udalosť a vykoná príslušnú obsluhu.
  4. Pokračuje v čakaní alebo ukončí aplikáciu.

Vhodné pre aplikáciu, kde používateľ sám určuje poradie akcií.

Konzolová simulácia cyklu

#include <iostream>
#include <string>

class Pocitadlo {
public:
    int hodnota{};

    void zvys() {
        ++hodnota;
    }
};

int main() {
    Pocitadlo pocitadlo{};
    std::string vstup;

    std::cout << "Z = zvysit, Q = koniec\n";
    while (std::getline(std::cin, vstup)) {
        if (vstup == "q" || vstup == "Q") {
            break;
        } else if (vstup == "z" || vstup == "Z") {
            pocitadlo.zvys();
            std::cout << "Hodnota: " << pocitadlo.hodnota << '\n';
        } else {
            std::cout << "Neznama volba. Zadaj Z alebo Q.\n";
        }
        std::cout << "Z = zvysit, Q = koniec\n";
    }
    std::cout << "Program sa ukoncil.\n";
}

Čo predstavuje simuláciu? Každý riadok vstupu predstavuje príkaz používateľa. Cyklus ho načíta, rozhodne, či ide o „zvýšiť“ alebo „koniec“, a vykoná reakciu. pocitadlo.zvys() je metóda, ktorú program zavolá po rozpoznaní simulovaného príkazu.

Obmedzenie: toto nie je skutočný GUI event loop. Konzola čaká na riadok textu; Win32 aplikácia prijíma správy od Windows a používa iný mechanizmus.

Zostavenie a spustenie – MSVC

  1. Ulož kód ako cyklus.cpp.
  2. Otvor Developer Command Prompt for VS 2022 a prejdi do priečinka súboru.
  3. Zostav: cl /std:c++17 /EHsc /W4 /Fe:cyklus.exe cyklus.cpp.
  4. Spusti cyklus.exe, napíš Z na zvýšenie počítadla a Q na ukončenie.

Konzolový príklad používa štandardné C++ a nepotrebuje Win32 API ani samostatné systémové knižnice.

Interaktívna kontrola

Čo sa má stať po tom, keď používateľ v GUI klikne na tlačidlo „Uložiť“?

Vyber najvhodnejší opis:

Praktická úloha: návrh cyklu udalostí

Cieľ: naplánovať udalosti a reakcie pre jednoduché počítadlo bez implementácie Win32 GUI.

Predpoklady: trieda, atribút, metóda, podmienka a cyklus.

  1. Vypíš možné udalosti: zvýšiť, vynulovať, ukončiť a neznámy vstup.
  2. Ku každej udalosti priraď reakciu programu.
  3. Urči, ktoré reakcie menia stav a ktorá ukončí cyklus.
  4. Prejdi scenár: zvýšiť, zvýšiť, neznámy vstup, vynulovať, ukončiť.

Očakávaný výsledok: tabuľka alebo diagram udalostí, obslúh a zmien stavu v správnom poradí.

Kritériá (5 b): udalosti (1), reakcie (2), zmena stavu správne určená (1), ukončenie cyklu (1).

  • Základná: doplň reakcie pre „zvýšiť“ a „ukončiť“.
  • Rozširujúca: doplň udalosť „vynulovať“ a urči nový stav.
  • Náročnejšia: navrhni, čo má aplikácia urobiť, ak počas ukladania dostane ďalšiu používateľskú udalosť.

Zhrnutie: 6 poznatkov

  1. Udalostne riadený program čaká na akcie používateľa alebo systému.
  2. Po prijatí udalosti ju program rozpozná a vykoná príslušnú obsluhu.
  3. Obsluha môže zavolať metódu a zmeniť stav objektu.
  4. Cyklus pokračuje, kým nenastane udalosť ukončenia.
  5. Konzolový vstup môže ilustrovať tok, ale nie je skutočným Win32 event loopom.
  6. Konkrétnu správovú slučku Windows budeme používať až v Win32 časti kurzu.

Kontrolné otázky

  1. Prečo GUI aplikácia nemôže predpokladať, že používateľ klikne v pevnom poradí?
  2. Aké sú hlavné kroky cyklu udalostí?
  3. Čo môže urobiť obsluha udalosti?
  4. Prečo konzolový príklad nie je Win32 aplikácia?
Učiteľská časť · odpovede, hodnotenie a podpora

Odpovede: používateľ určuje poradie akcií; čakanie, prijatie, rozpoznanie a obsluha, návrat k čakaniu alebo ukončenie; obsluha môže zmeniť stav, zavolať metódu či aktualizovať zobrazenie; konzolová ukážka číta textový vstup a nepoužíva Windows správovú slučku ani GUI udalosti.

Interaktívna kontrola: správna je B. Nech žiak vymenuje udalosť, obsluhu a následnú akciu.

Hodnotenie: 5 bodov podľa kritérií praktickej úlohy. Hodnoť správnu logiku scenára, nie konkrétne grafické znázornenie.

Podpora: priprav kartičky so vstupmi a kartičky s reakciami; žiak ich spáruje a potom zoradí podľa scenára. Pri odlíšení od Win32 zdôrazni, čo simulácia má a čo nemá.

Poznámky a povinné vedomosti, ktoré si zapamätáš z hodiny

  • Udalostne riadený program čaká na udalosti namiesto vykonania jediného pevného postupu.
  • Udalosť sa prijme, rozpozná a odovzdá príslušnej obsluhe.
  • Obsluha môže zavolať metódu a zmeniť stav aplikácie.
  • Konzolová simulácia vysvetľuje princíp, no nie je skutočný Win32 event loop.

Nadväznosť: hodina 11 začne zapuzdrením dát a rozhraním triedy: ako chrániť stav a riadiť prístup k nemu.
