Modelovanie reálneho problému objektmi

Od opisu zadania k rozumným triedam, objektom a údajom

4. ročník SPŠ · C++ príprava pre Win32

Objektový návrh sa začína porozumením problému. Najprv zistíme, čo má program robiť, potom vyberieme dôležité entity a údaje, ktoré potrebuje uchovať. V tejto hodine navrhneme jednoduchý model pre evidenciu študentov, ktorý sa neskôr stane spoločnou ukážkovou líniou kurzu.

Od potreby používateľa k dátovému modelu
Začiatok hodiny: skontrolujte pracovisko a počítač; závadu ihneď oznám vyučujúcemu. Poškodené alebo nebezpečné zariadenie nepoužívajte. Stručný súhrn pošli cez EduPage podľa pokynov.

Ciele hodiny

Na konci hodiny dokážete:

  • z textového zadania vybrať entity, o ktorých program uchováva údaje;
  • navrhnúť vhodné atribúty pre jednu entitu;
  • odlíšiť požiadavku programu od konkrétnej implementácie;
  • nakresliť jednoduchý model a vytvoriť jeho ukážkové inštancie v C++.

Zadanie používateľa

„Chcem si udržiavať zoznam študentov. Pri každom potrebujem vedieť jeho identifikačné číslo, meno a triedu. Chcem vedieť študenta pridať a neskôr ho nájsť.“

Skôr než budeme písať okno alebo databázu, potrebujeme určiť, aké údaje vlastne modelujeme.

Postup modelovania

1 · PorozumejČo chce používateľ robiť?
2 · Nájdite entityO čom sa uchovávajú údaje?
3 · Vyberte údajeČo vieme o každej entite?
4 · SkontrolujteStačia údaje pre požadované úlohy?

V tomto zadaní je hlavnou entitou študent. Program bude pracovať s viacerými študentmi, preto každý konkrétny študent môže byť samostatným objektom triedy Student.

Model evidencie študentov

Požiadavka

  • každého študenta jednoznačne rozpoznať;
  • zobraziť jeho meno a triedu;
  • pripraviť sa na pridanie a vyhľadanie záznamu.

Prvý návrh údajov

  • id – identifikátor, napríklad celé číslo;
  • meno – textové meno;
  • trieda – textové označenie triedy.
Požiadavka: evidencia študentov
                │
                ▼
          trieda Student
       ┌────────┼─────────┐
       id      meno      trieda
        │        │          │
        ▼        ▼          ▼
   studentA  studentB   studentC

Identifikátor odlišuje záznam aj vtedy, keď majú dvaja študenti rovnaké meno. V prvej ukážke ho priradíme ručne; neskôr budeme riešiť vytváranie a ukladanie záznamov.

C++ náčrt modelu

#include <iostream>
#include <string>

class Student {
public:
    int id{};
    std::string meno;
    std::string trieda;
};

int main() {
    Student studentA{};
    studentA.id = 101;
    studentA.meno = "Jana Novakova";
    studentA.trieda = "IV.A";

    Student studentB{};
    studentB.id = 102;
    studentB.meno = "Peter Kral";
    studentB.trieda = "IV.B";

    std::cout << studentA.id << " - " << studentA.meno
              << " (" << studentA.trieda << ")\n";
    std::cout << studentB.id << " - " << studentB.meno
              << " (" << studentB.trieda << ")\n";
}

Čo tu modelujeme? Trieda Student predstavuje typ entity. Premenné studentA a studentB sú dve inštancie s oddelenými hodnotami. Zatiaľ neriešime okno, databázu ani zoznam; najprv overujeme, či zvolené údaje vystihujú požiadavku.

Zostavenie a spustenie – MSVC

  1. Uložte kód ako studenti.cpp.
  2. Otvorte Developer Command Prompt for VS 2022 a prejdite do priečinka súboru.
  3. Zostavte: cl /std:c++17 /EHsc /W4 /Fe:studenti.exe studenti.cpp.
  4. Spustite: studenti.exe. Výstup má obsahovať dva rozdielne záznamy.

Ide o konzolovú ukážku štandardného C++, nie o Win32 aplikáciu. Nepotrebuje Windows API ani samostatné systémové knižnice.

Kontrolné otázky pri návrhu

  • Je každá vybraná informácia potrebná pre požadované činnosti?
  • Vie identifikátor odlíšiť študentov s rovnakým menom?
  • Je hodnota vlastnosťou jedného študenta, alebo patrí celej aplikácii?
  • Nepridávame teraz údaje, ktoré zadanie vôbec nevyžaduje?

Rozsah modelu

Dobrý prvý model je dosť malý na pochopenie a dosť úplný na splnenie zadania. Údaje ako obľúbená farba či domáca adresa do tejto evidencie nepridávame bez dôvodu. Neskoršie požiadavky môžu model upraviť.

Model je zjednodušenie reality. Nepotrebujeme opísať celý život študenta, iba údaje potrebné pre konkrétnu aplikáciu.

Interaktívna kontrola

Zadanie vyžaduje študenta jednoznačne nájsť a zobraziť jeho meno. Ktorá voľba je najvhodnejšia pre prvý model?

Vyberte odpoveď:

Praktická úloha: model školskej knižnice

Cieľ: odvodiť malý dátový model z požiadaviek používateľa.

Predpoklady: trieda, inštancia a atribúty z predchádzajúcich hodín.

Zadanie: knižnica chce evidovať knihy, ich názov, autora a dostupnosť, aby vedela vypísať dostupné knihy.

  1. Podčiarkni v texte veci, o ktorých sa uchovávajú údaje.
  2. Navrhnite triedu a minimálne tri atribúty vrátane vhodných typov.
  3. Uveďte príklad dvoch inštancií s rôznymi údajmi.
  4. Zdôvodnite, prečo každý atribút potrebujeme vzhľadom na požiadavku.

Očakávaný výsledok: diagram alebo krátky C++ model triedy Kniha a dve ukážkové inštancie.

Kritériá (5 b): správna entita (1), relevantné atribúty a typy (2), dve rozdielne inštancie (1), zdôvodnenie podľa zadania (1).

  • Základná: vyberte atribúty z ponuky názov, autor, dostupnosť, farba obalu, rozmery police.
  • Rozširujúca: doplňte jedinečný identifikátor a vysvetlite jeho účel.
  • Náročnejšia: navrhnite, ako by model zmenila požiadavka evidovať vypožičania a dátum vrátenia.

Zhrnutie: 6 poznatkov

  1. Modelovanie začína pochopením požiadavky, nie písaním kódu.
  2. Entita je vec alebo pojem, o ktorom aplikácia potrebuje uchovávať údaje.
  3. Trieda môže reprezentovať typ entity a jej atribúty.
  4. Atribúty vyberáme podľa požadovaných činností programu.
  5. Identifikátor pomáha rozlíšiť záznamy aj pri rovnakých menách.
  6. Model je účelové zjednodušenie; zbytočné údaje nepridávame bez dôvodu.

Učiteľská časť · odpovede, hodnotenie a podpora

Odpovede: najprv porozumieť požiadavke; identifikátor rozlišuje záznamy s rovnakým menom; údaj pridáme, ak ho potrebuje niektorá požadovaná činnosť; model uchováva iba informácie potrebné pre aplikáciu a jej rozsah.

Interaktívna kontrola: najlepšia je A. V úplnom zadaní je potrebný aj údaj o triede; formulácia otázky cieli na nájdenie a zobrazenie, preto môže byť prvý model minimálny. Poukáž na to, že model sa spresní podľa všetkých požiadaviek.

Hodnotenie: 5 bodov podľa kritérií praktickej úlohy. Uznaj vhodné typy a alternatívne identifikátory, ak ich žiak zdôvodní.

Podpora: rozdeľ zadanie na tri otázky: „Čo evidujeme?“, „Čo o tom potrebujeme vedieť?“ a „Na čo tieto údaje použijeme?“. Použi farebné kartičky pre entity, atribúty a činnosti.

Poznámky a povinné vedomosti, ktoré si zapamätáte z hodiny

  • Najprv rozumiem požiadavke a až potom navrhujem triedu.
  • Modelujem iba entity a údaje potrebné pre aplikáciu.
  • Identifikátor pomáha jednoznačne rozlíšiť záznam.
  • Model je zjednodušený opis reality a môže sa meniť s požiadavkami.

Nadväznosť: hodina 7 sa zameria na objekty a ich vlastnosti a na to, ako objekty vznikajú a zanikajú počas behu programu.
