Nastavenia, zostavenie a spustenie

Priprav VS Code a MSVC a zostav svoj prvý overovací program

4. ročník SPŠ · Windows 10/11 · C++17

V minulej hodine sme rozpoznali editor, kompilátor a SDK. Teraz overíme, že spolupracujú: VS Code upraví zdrojový súbor, pripravené prostredie sprístupní MSVC a kompilátor vytvorí spustiteľný program.

VS Code + C/C++ rozšírenie + MSVC v143 + Windows SDK
Začiatok hodiny: skontrolujte pracovisko a počítač; závadu ihneď oznám vyučujúcemu. Poškodené alebo nebezpečné zariadenie nepoužívajte. Stručný súhrn pošli cez EduPage podľa pokynov.

Ciele hodiny

Na konci hodiny dokážete:

  • overiť, či je nainštalované Microsoft C/C++ rozšírenie a nástroje MSVC;
  • vysvetliť, prečo spustiť VS Code z Developer Command Prompt;
  • zostaviť jednoduchý C++17 program príkazom cl;
  • spustiť výsledný súbor a rozlíšiť chybu prostredia od chyby kódu.

Čo dnes zostavíme?

Malý konzolový program potvrdí, že kompilátor a základná C++ knižnica fungujú. Nie je to ešte Win32 aplikácia: vytvorenie prvého projektu s oknom a nastaveniami linkeru je témou hodiny 25.

Ak nástroj chýba, nemeň systémovú inštaláciu bez pokynu správcu učebne; zaznamenajte, ktorá súčasť chýba, a oznám to vyučujúcemu.

Príprava VS Code a MSVC

  1. Spustite Developer Command Prompt for VS 2022. Toto prostredie nastaví cesty, ktoré MSVC potrebuje pre kompilátor, hlavičky a knižnice.
  2. Prejdite do pracovného priečinka s kurzom alebo si podľa pokynov otvorte pripravený priečinok cvičenia. Neukladaj projekt do priečinka inštalácie Visual Studio.
  3. V tom istom prompt-e spustite code ., aby sa VS Code otvoril z pripraveného prostredia MSVC.
  4. Vo VS Code otvorte Command Palette (Ctrl+Shift+P) a vyhľadaj C/C++: Select IntelliSense Configuration. Vyberte Microsoft C++/MSVC x64, ak je táto voľba ponúknutá.
  5. IntelliSense pomáha pri dopĺňaní a kontrolovaní kódu; úspešné IntelliSense samo osebe ešte nedokazuje, že zostavenie prebehlo.

Alternatívne môžete zostavovať z Developer Command Prompt priamo a používať VS Code iba ako editor. V tomto kurze zostaneme pri MSVC; príkazy MinGW/GCC sú odlišné.

Overovací program

#include <iostream>

int main() {
    std::cout << "C++17 a MSVC funguju." << std::endl;
    return 0;
}

Zostavenie cez MSVC

  1. Vo VS Code vytvorte súbor overenie.cpp v otvorenom pracovnom priečinku a uložte ho.
  2. V integrovanom termináli, ktorý zdedil prostredie Developer Command Prompt, overte priečinok príkazom cd; prípadne použite pôvodný Developer Command Prompt.
  3. Zostavte príkazom cl /std:c++17 /EHsc /W4 /Fe:overenie.exe overenie.cpp.
  4. Ak sa zobrazí úspešná kompilácia a vznikne overenie.exe, spustite overenie.exe.
  5. Očakávaný výstup je C++17 a MSVC funguju.

Čo znamenajú prepínače? /std:c++17 vyberie jazykový štandard, /EHsc zapne štandardný režim spracovania výnimiek C++, /W4 zapne vyššiu úroveň upozornení a /Fe: určí názov výstupného programu.

Toto je konzolový overovací program. Na Windows API ešte nevolá, preto nepotrebuje Windows SDK knižnice ani linkerové závislosti Win32.

Správny pracovný priečinok

  • VS Code otvorte ako priečinok/workspace, nie iba jeden súbor.
  • Terminál musí vidieť zdrojový súbor, ktorý uvádzate v príkaze.
  • Výsledný súbor vznikne v aktuálnom pracovnom priečinku, ak nepoužijete inú cestu.
  • Priečinok výsledného programu a zdrojového súboru si pred spustením overte.

Ak zostavenie zlyhá

  • cl is not recognized: terminál pravdepodobne nezdedil MSVC prostredie.
  • cannot open source file: skontrolujte názov súboru a aktuálny priečinok.
  • Chyby syntaxe s číslom riadka: otvorte uvedený súbor a opravte prvú chybu; ďalšie môžu byť jej následkom.
  • Chýbajúci Windows SDK sa pri tomto konzolovom príklade nemusí prejaviť; bude dôležitý pri Win32 projekte.

Interaktívna kontrola

VS Code zvýrazňuje kód bez chýb, ale príkaz cl vypíše, že ho systém nepozná. Čo overíte ako prvé?

Vyberte najlepší krok:

Praktická úloha: zostavte a spustite

Cieľ: získať reprodukovateľný dôkaz, že editor, MSVC a spustenie programu fungujú spolu.

Predpoklady: Windows, VS Code, C/C++ rozšírenie, MSVC v143 a Developer Command Prompt.

  1. Otvorte pripravený pracovný priečinok ako workspace.
  2. Vytvorte a uložte overenie.cpp podľa ukážky.
  3. Spustite uvedený príkaz MSVC a zaznamenajte, či vznikol overenie.exe.
  4. Spustite program a zapíšte jeho výstup.
  5. Ak sa vyskytne chyba, zaraď ju: prostredie/nástroj, cesta/súbor alebo zdrojový kód.

Očakávaný výsledok: zostavený a spustený program s očakávaným výstupom, alebo presne pomenovaná prekážka na nahlásenie.

Kritériá (5 b): správny workspace (1), zdroj uložený (1), príkaz MSVC správne použitý (1), program spustený/výstup zaznamenaný (1), chyba správne klasifikovaná (1).

  • Základná: doplňte chýbajúci riadok výpisu do pripraveného súboru.
  • Rozširujúca: zmeňte výstupný názov cez /Fe: a spustite program pod novým názvom.
  • Náročnejšia: opíšte kroky, ktorými by ste odlíšili IntelliSense upozornenie od chyby kompilátora.

Zhrnutie: 6 poznatkov

  1. VS Code je editor; C/C++ rozšírenie poskytuje jazykové funkcie, nie kompilátor.
  2. MSVC v143 zostavuje C++ program a Windows SDK poskytuje Windows hlavičky a knižnice.
  3. MSVC potrebuje Developer Command Prompt/PowerShell alebo zdedené a správne nastavené prostredie.
  4. Príkaz cl zostaví zdroj; /Fe: určí názov EXE.
  5. IntelliSense a kompilácia sú dve odlišné kontroly.
  6. Prvý projekt s oknom Win32 a jeho konfiguráciou vytvoríme na hodine 25.

Učiteľská časť · odpovede, hodnotenie a podpora

Odpovede: nainštalovaný kompilátor/linker; prompt nastavuje cesty k MSVC, hlavičkám a knižniciam; /Fe: určuje názov výstupného programu; ukážka používa iba štandardnú knižnicu a konzolu, nevolá Windows API.

Interaktívna kontrola: správna je B. Chyba „cl is not recognized“ poukazuje najprv na dostupnosť kompilátora v prostredí, nie na syntaktický problém.

Hodnotenie: 5 bodov podľa kritérií praktickej úlohy. Ak je školská inštalácia nefunkčná, uznaj presnú diagnostiku a zdokumentovanú chybu ako výsledok práce.

Podpora: priprav vopred Developer Command Prompt a otvorený projektový priečinok. Nechaj žiakov meniť iba zdrojový súbor a nespúšťaj inštalácie počas hodiny bez správcu.

Poznámky a povinné vedomosti, ktoré si zapamätáte z hodiny

  • VS Code ani jeho C/C++ rozšírenie samy neobsahujú kompilátor.
  • MSVC zostavuje program; Developer Prompt pripraví potrebné prostredie.
  • Príkaz cl /std:c++17 /EHsc /W4 /Fe:overenie.exe overenie.cpp zostaví tento konzolový príklad.
  • Úspešné zostavenie a IntelliSense sú rozdielne veci.

Nadväznosť: hodina 25 vytvorí prvý natívny Win32 projekt a vysvetlí jeho zdrojové súbory a konfiguráciu.
