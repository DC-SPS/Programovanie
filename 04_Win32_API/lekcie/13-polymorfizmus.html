Polymorfizmus: prekrývanie metód

Rovnaké volanie, správanie podľa skutočného typu objektu

4. ročník SPŠ · C++ príprava pre Win32

V hodine 12 sme vytvorili základnú a odvodenú triedu. Teraz sa pozrieme na polymorfizmus: cez spoločné rozhranie môžeme zavolať rovnakú operáciu a získať správanie podľa skutočného typu objektu. V C++ to pre tento prípad umožňujú virtuálne metódy.

Spoločný príkaz · špecifická reakcia
Začiatok hodiny: skontroluj pracovisko a počítač; závadu ihneď oznám vyučujúcemu. Poškodené alebo nebezpečné zariadenie nepoužívaj. Stručný súhrn pošli cez EduPage podľa pokynov.

Ciele hodiny

Na konci hodiny dokážeš:

  • vysvetliť polymorfizmus na príklade viacerých odvodených typov;
  • rozpoznať virtuálnu metódu v základnej triede a jej prekrytie;
  • opísať, prečo referencia na základný typ môže viesť k metóde odvodeného objektu;
  • predpovedať výstup jednoduchej C++ ukážky.

Motivácia: rôzne typy upozornení

Aplikácia môže mať študenta aj učiteľa. Oboch možno požiadať „vypíš svoju rolu“, no každý poskytne vlastnú odpoveď. Používajú spoločné rozhranie, ale správanie prispôsobí konkrétny objekt.

Nadväznosť: dedičnosť poskytne spoločný typ. Virtuálna metóda umožní, aby sa volaná implementácia vybrala podľa skutočného objektu.

Tok polymorfného volania

Spoločné rozhranieOsoba::vypisRolu()
ReferenciaOsoba& odkazuje na objekt
Virtuálne volanieprogram zistí skutočný typ
Špecifická reakciaStudent alebo Ucitel

Bez virtual by obyčajné volanie cez základný typ nevyberalo odvodenú implementáciu týmto spôsobom. Kľúčové slovo override v odvodenej triede označí, že metóda má prekryť virtuálnu metódu predka; kompilátor vie zachytiť nesúlad podpisu.

Ukážka v C++17

#include <iostream>

class Osoba {
public:
    virtual void vypisRolu() const {
        std::cout << "Som osoba" << std::endl;
    }
};

class Student : public Osoba {
public:
    void vypisRolu() const override {
        std::cout << "Som student" << std::endl;
    }
};

class Ucitel : public Osoba {
public:
    void vypisRolu() const override {
        std::cout << "Som ucitel" << std::endl;
    }
};

int main() {
    Student student;
    Ucitel ucitel;
    Osoba& osoba1 = student;
    Osoba& osoba2 = ucitel;

    osoba1.vypisRolu();
    osoba2.vypisRolu();
}

Výstup: Som student, potom Som ucitel. Premenné osoba1 a osoba2 majú typ referencie Osoba&, no odkazujú na odlišné objekty. Keďže metóda je virtuálna, zavolá sa prekrytá verzia podľa skutočného typu objektu.

Rozsah dnešnej ukážky: objekty aj referencie žijú v main; nepoužívame dynamickú alokáciu, ukazovatele ani kontajnery. Zameriame sa na virtuálne volanie.

  2. Otvor Developer Command Prompt for VS 2022 a prejdi do priečinka súboru.
  3. Zostav: cl /std:c++17 /EHsc /W4 /Fe:polymorfizmus.exe polymorfizmus.cpp.
  4. Spusti polymorfizmus.exe a porovnaj obe odpovede.

Konzolový príklad používa štandardné C++, nie Win32 API, a nepotrebuje samostatné systémové knižnice.

Základné pojmy

  • Virtuálna metóda: metóda označená virtual v základnej triede.
  • Prekrytie: odvodená trieda poskytne metódu s rovnakým podpisom.
  • override: potvrdzuje zámer prekryť virtuálnu metódu.
  • Polymorfné volanie: vyberie implementáciu podľa skutočného objektu cez základné rozhranie.

Typické chyby

  • Chýbajúce virtual v základnej triede.
  • Odlišný podpis odvodeného člena, takže nejde o zamýšľané prekrytie.
  • Vynechané override, ktoré by pomohlo chybu odhaliť.
  • Predpoklad, že dedičnosť sama osebe vždy znamená polymorfné volanie.

  • Základná: doplň jedno odvodenie a jednu prekrytú metódu.
  • Rozširujúca: pridaj tretiu rolu a vysvetli, čo zostáva spoločné.
  • Náročnejšia: predpovedz, ako by sa zmenil výsledok, keby sa z virtual odstránilo.

Zhrnutie: 6 poznatkov

  1. Polymorfizmus umožňuje rovnakému volaniu vykonať správanie podľa typu objektu.
  2. Základná trieda označí metódu slovom virtual.
  3. Odvodená trieda prekryje metódu rovnakým podpisom.
  4. override kontroluje, že ide o zamýšľané prekrytie.
  5. Volanie cez základnú referenciu môže vybrať odvodenú implementáciu.
  6. Dedičnosť bez virtuálnej metódy sama osebe toto dynamické správanie nezabezpečí.

Učiteľská časť · odpovede, hodnotenie a podpora

Odpovede: virtual povoľuje dynamický výber implementácie pri volaní cez základný typ; override overuje, že podpis skutočne prekrýva virtuálnu metódu predka; referencia viaže základné rozhranie na konkrétny objekt Ucitel a virtuálne volanie vyberie jeho implementáciu; nie, metóda musí byť virtuálna v základnej triede.

Interaktívna kontrola: správna je B. Zadaj modelovú otázku: „Aký typ má referencia a na aký objekt odkazuje?“

Hodnotenie: 5 bodov podľa kritérií praktickej úlohy. Pri názvoch tried povoľ diakritiku alebo ASCII podľa zvoleného kódovania zdroja.

Podpora: ukáž najprv priamu metódu bez referencií a potom pridaj jednu základnú referenciu. Farebne odlíš statický typ referencie od skutočného typu objektu.

Poznámky a povinné vedomosti, ktoré si zapamätáš z hodiny

  • Virtuálna metóda sa označuje v základnej triede slovom virtual.
  • Odvodená trieda ju môže prekryť; použijem override.
  • Pri volaní cez základnú referenciu sa vyberie verzia podľa skutočného typu objektu.
  • Polymorfizmus umožňuje pracovať cez spoločné rozhranie a získať špecifickú reakciu.

Nadväznosť: hodina 14 navrhne spoločné rozhranie a precvičí, ako polymorfizmus zjednodušuje prácu s viacerými typmi.
