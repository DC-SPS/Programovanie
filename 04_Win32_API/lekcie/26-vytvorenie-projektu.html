Prepojenie s hodinou 25

Minule sme vytvorili prve_okno.cpp a priamo z neho spustili cl. Dnes rozdelíme kompiláciu a linkovanie, aby bolo viditeľné, ako zdrojový kód a knižnice systému vytvoria finálny EXE.

Čo patrí do priečinka projektu?

PrveWin32/ ├── prve_okno.cpp zdrojový C++ kód, ktorý píšeme ├── resource.h identifikátory, ak neskôr pridáme zdroje ├── app.rc voliteľný textový súbor Windows zdrojov ├── .vscode/ │ └── tasks.json voliteľná úloha na zostavenie v VS Code └── build/ výstupy zostavenia, možno ich znovu vytvoriť ├── prve_okno.obj strojový kód jedného preloženého súboru ├── prve_okno.exe výsledná aplikácia po linkovaní └── prve_okno.pdb ladiace symboly, ak ich build vytvorí

Pre dnešnú ukážku stačí jeden súbor .cpp. Hlavička windows.h je súčasť Windows SDK a píšeme jej názov cez #include; nekopírujeme SDK hlavičku do projektu. Súbor .obj je prechodný výstup kompilátora, kým .exe je spustiteľný výsledok linkera. .pdb pomáha ladiť; nie je to zdrojový kód.

Do odovzdávaného projektu patrí zdrojový kód a potrebné vlastné zdroje. Výstupy v build/ možno vymazať a opätovne vytvoriť zostavením. Cudzie súbory ani SDK hlavičky do projektu nekopíruj.

Od zdrojového kódu k programu

1 · Preprocesorhlavičky a makrá
2 · Kompilátor.cpp → .obj
3 · Linker.obj + .lib → .exe
4 · Windowsspustenie aplikácie

Hlavička dodá deklarácie, aby kompilátor poznal použité funkcie a typy. Kompilátor preloží C++ súbor do objektového súboru. Linker spojí objektové súbory s potrebnými knižnicami. Pri príklade z hodiny 25 je User32.lib importná knižnica pre funkcie okien, napríklad CreateWindowExW a GetMessageW.

C++ rozhodnutia: jazyková verzia, zdrojové súbory a makrá. Nastavenia Windows/MSVC: cieľový subsystem, SDK, linker a systémové knižnice. Nastavenia nemenia význam jednotlivých volaní Win32 API, ale určujú, ako sa program zostaví a spustí.

Nastavenia, ktoré dnes potrebujeme

  • /std:c++17 – zvolí štandard C++17, na ktorom sa zhodneme v kurze.
  • /EHsc – zapne štandardné spracovanie C++ výnimiek pre synchronný kód.
  • /W4 – zapne úroveň upozornení MSVC; upozornenie nie je vždy chyba, ale treba mu porozumieť.
  • /DUNICODE /D_UNICODE – definujú Unicode makrá pre Windows hlavičky a C runtime; tento program aj tak používa explicitné názvy API s príponou W.
  • /c – iba skompiluje, bez linkovania EXE.
  • /Fo:build\prve_okno.obj – určí názov objektového súboru.
  • /Fe:build\prve_okno.exe – určí názov výstupného EXE.
  • /link /SUBSYSTEM:WINDOWS – odovzdá linkeru nastavenie GUI subsystemu. Pre tento príklad sa linkuje User32.lib.

Každý prepínač má konkrétny účel. Pri diagnostike si všimnite, či hlási chybu kompilátor (cl) alebo linker (link): chýbajúci symbol API sa často prejaví až pri linkovaní.

Minimálny zdrojový súbor a reprodukovateľný build

Uložte nasledujúci úplný zdrojový súbor ako prve_okno.cpp. Je to to isté jednoduché okno z predchádzajúcej hodiny.

#include <windows.h>

constexpr wchar_t CLASS_NAME[] = L"PrveWin32Okno";

LRESULT CALLBACK WindowProc(HWND hwnd, UINT message,
                            WPARAM wParam, LPARAM lParam)
{
    if (message == WM_DESTROY) {
        PostQuitMessage(0);
        return 0;
    }
    return DefWindowProcW(hwnd, message, wParam, lParam);
}

int WINAPI wWinMain(HINSTANCE instance, HINSTANCE, PWSTR, int show)
{
    WNDCLASSEXW wc{};
    wc.cbSize = sizeof(wc);
    wc.lpfnWndProc = WindowProc;
    wc.hInstance = instance;
    wc.hCursor = LoadCursorW(nullptr, IDC_ARROW);
    wc.hbrBackground = GetSysColorBrush(COLOR_WINDOW);
    wc.lpszClassName = CLASS_NAME;

    if (!RegisterClassExW(&wc)) return 1;

    HWND hwnd = CreateWindowExW(0, CLASS_NAME, L"Prvé okno",
        WS_OVERLAPPEDWINDOW, CW_USEDEFAULT, CW_USEDEFAULT, 640, 400,
        nullptr, nullptr, instance, nullptr);
    if (!hwnd) return 1;

    ShowWindow(hwnd, show);
    UpdateWindow(hwnd);
    MSG msg{};
    BOOL result;
    while ((result = GetMessageW(&msg, nullptr, 0, 0)) > 0) {
        TranslateMessage(&msg);
        DispatchMessageW(&msg);
    }
    return result == -1 ? 1 : static_cast<int>(msg.wParam);
}

Zostavenie v dvoch krokoch (MSVC v143)

  1. Vytvorte priečinok projektu a podpriečinok build. Otvorte projekt vo VS Code z Developer Command Prompt for VS 2022, aby boli dostupné cl, linker a Windows SDK.
  2. Prelož zdrojový súbor na objektový súbor:
    cl /nologo /std:c++17 /EHsc /W4 /DUNICODE /D_UNICODE /c prve_okno.cpp /Fo:build\prve_okno.obj
  3. Skontrolujte, že vznikol build\prve_okno.obj. Zatiaľ to nie je aplikácia, ktorú spustíme.
  4. Pripojte objektový súbor a User32:
    link build\prve_okno.obj user32.lib /OUT:build\prve_okno.exe /SUBSYSTEM:WINDOWS
  5. Spustite z rovnakého terminálu build\prve_okno.exe, zavri okno a overte, že proces skončil.

Alternatíva, jeden príkaz MSVC: cl /nologo /std:c++17 /EHsc /W4 /DUNICODE /D_UNICODE /Fe:build\prve_okno.exe prve_okno.cpp /link /SUBSYSTEM:WINDOWS user32.lib. Kompilátor pri bežnom linkovaní vykoná aj kompiláciu a zavolá linker. Dvojkrokový postup používame na pozorovanie súboru .obj.

Kontext: príkazy vyššie sú výhradne pre MSVC. MinGW/GCC používa iné prepínače a linkovaciu syntax, preto ich nekombinuj s týmto príkazom. Potrebné knižnice: User32.lib; príklad nepoužíva GDI.

Typické chyby a diagnostika

  • cl is not recognized: terminál nemá pripravené prostredie MSVC; otvorte Developer Command Prompt/PowerShell.
  • cannot open include file: windows.h: chýba alebo nie je dostupné Windows SDK.
  • LNK2019 unresolved external symbol: skontrolujte, či objektový súbor obsahuje definíciu a či si pri linkovaní uviedol User32.lib.
  • Vznikne konzola navyše: overte /SUBSYSTEM:WINDOWS a vstupný bod GUI wWinMain.
  • EXE sa nenašlo: skontrolujte, či zostavenie skončilo bez chyby a či cesta zodpovedá prepínaču /OUT alebo /Fe.

Najprv si prečítajte prvú diagnostickú chybu, nie iba posledný riadok. Opravte konkrétnu príčinu a zostavte znovu.

Zhrnutie: 7 poznatkov

  1. Súbor .cpp obsahuje zdrojový kód, ktorý upravujeme.

Učiteľská časť · odpovede, hodnotenie a podpora

Kontrolné odpovede: .cpp je vstupný zdroj, .obj výstup kompilácie a .exe výstup linkeru; /c vynechá linkovanie; /Fo pomenúva objekt a /Fe EXE; LNK2019 je chyba linkeru, typicky nedefinovaný alebo nepripojený symbol/knižnica.

Interaktívna kontrola: správna je B. Linker musí dostať objektový súbor, závislosti a správnu konfiguráciu cieľa.

Hodnotenie: 5 bodov podľa praktických kritérií. Ak školský počítač nemá funkčné SDK alebo toolchain, uznaj správne vysvetlený postup a diagnostiku.

Podpora: daj žiakovi vytlačenú schému .cpp → .obj → .exe a postupne zakry názvy prepínačov. Nech najprv označí vstup, kompilátorový výstup, linkerové vstupy a finálny program.

Poznámky a povinné vedomosti, ktoré si zapamätáte z hodiny

  • .cpp je zdroj, .obj medzivýstup kompilátora a .exe výsledok linkera.
  • /c skompiluje bez linkovania; linker potrebuje objekt a príslušné knižnice.
  • /std:c++17, /W4, /Fo a /Fe majú odlišné úlohy.
  • Win32 GUI build používa subsystem Windows; tento príklad linkuje User32.lib.
  • Build príkaz je súčasť dokumentácie projektu a musí uvádzať toolchain.

Nadväznosť: hodina 27 začne pracovať so schránkou Windows; k projektu sa budeme vracať pri ďalších natívnych API.
