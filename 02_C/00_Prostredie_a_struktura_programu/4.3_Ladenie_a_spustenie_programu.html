4.3 Ladenie a spustenie programu v jazyku C

1 × 45 min Tematický celok 4 C17 VS Code + GCC

Nadväznosť: V prednáške 4.2 ste vytvorili program s funkciou main a výpisom cez printf. Teraz si precvičíte celý postup uloženia, prekladu a spustenia a naučíte sa postupovať, keď kompilátor alebo výsledok upozorní na problém.
Ciele, predpoklady a pomôcky Žiak rozlíši zdrojový súbor a spustiteľný program, preloží jednoduchý súbor C17 pomocou GCC, nájde miesto jednoduchej syntaktickej chyby podľa diagnostického hlásenia a opíše základné kroky ladenia. Predpoklady: lekcia 4.2, funkcia main, printf a príkaz prekladu. Pomôcky: VS Code, GCC a terminál; debugger je voliteľný a môže byť zobrazený učiteľom.

Cieľ hodiny

Na konci hodiny dokážete preložiť a spustiť jednoduchý program v C17, nájsť a opraviť jednoduchú chybu v kóde a vysvetliť, prečo je dôležité overiť výstup programom aj človekom.

1. Od zdrojového kódu k spustenému programu

1 · Uložtenapríklad main.c
2 · Preložtepomocou GCC
3 · Opravtechyby z diagnostiky
4 · Spustitev termináli
5 · Overteskutočný výstup

Uloženie súboru samo osebe program nespustí. Najprv GCC preloží zdrojový kód; až potom spúšťame vytvorený program. Ak preklad zlyhá, treba najprv prečítať hlásenie a opraviť zdrojový kód.

gcc -std=c17 -Wall -Wextra -Wpedantic main.c -o program
  • -std=c17 nastaví jazykový režim C17;
  • -Wall -Wextra -Wpedantic zapne skupiny užitočných upozornení;
  • main.c je vstupný zdrojový súbor;
  • -o program určuje názov vytvoreného programu.

V PowerShelli spustíme program príkazom .\program.exe; v Linuxe príkazom ./program. Pri opätovnom preklade skontrolujte, či príkaz skončil bez chýb, a až potom spúšťajte novovytvorený program.

2. Ako čítať chybové hlásenie

Diagnostické hlásenie kompilátora zvyčajne obsahuje názov súboru, číslo riadka, druh problému a krátky opis. Číslo riadka je pomôcka: chyba môže byť aj tesne pred označeným miestom.

#include <stdio.h>

int main(void) {
    printf("Program sa spusta\n")
    return 0;
}

Všimnite si chýbajúcu bodkočiarku na konci volania printf. GCC môže vypísať názov súboru a riadok, kde na problém narazilo, a očakávaný symbol. Hlásenie prečítajte, pozrite sa na označený riadok aj predchádzajúci riadok, opravte jednu vec a preložte znova.

#include <stdio.h>

int main(void) {
    printf("Program sa spusta\n");
    return 0;
}

Užitočné pravidlo: riešte prvú zmysluplnú chybu v poradí. Jedna chyba môže spôsobiť viac následných hlásení, preto neopravujte všetky upozornenia naslepo naraz.

3. Chyba pri preklade alebo chyba v riešení?

Chyba syntaxe

Program porušuje pravidlá zápisu jazyka, napríklad chýba bodkočiarka. Kompilátor zvyčajne nedokončí vytvorenie programu.

Chyba v logike

Program sa preloží a spustí, ale urobí alebo vypíše niečo iné, než sme zamýšľali. Kompilátor nemusí vedieť, čo sme chceli dosiahnuť.

Príklad: požadovaný výpis je „Test sa zacina“, ale text v príkaze printf omylom hovorí „Test sa konci“. Zápis môže byť platný, no význam je nesprávny.

Pri hľadaní chyby si najprv zapíšte očakávané správanie. Potom porovnajte jednotlivé kroky programu so skutočným výstupom a zúžte miesto problému.

4. Základný postup ladenia

  1. Opíšte problém: čo ste očakávali a čo sa naozaj stalo?
  2. Skontrolujte najbližší zdroj: súbor, riadok, terminálový príkaz a chybové hlásenie.
  3. Zúžte miesto chyby: sledujte vykonávanie od začiatku a overujte výstup po jednotlivých krokoch.
  4. Urobte jednu malú opravu: nemeňte viac vecí naraz.
  5. Zopakujte preklad a test: potvrďte, že problém zmizol a ostatný očakávaný výstup zostal správny.

V debuggeri možno nastaviť bod prerušenia (breakpoint), ktorý dočasne zastaví program na vybranom riadku. Potom možno vykonávať príkazy postupne a sledovať dostupné údaje. V tejto úvodnej hodine používame debugger len na ukážku; jeho nastavenie závisí od nainštalovaných nástrojov.

Voliteľná ukážka pre učiteľa Ak je pripravené rozšírenie C/C++ pre VS Code a debugger, nastavte breakpoint na volanie printf, spustite ladenie a ukážte krokové vykonávanie (Step Over). Neinštalujte ani nekonfigurujte nástroje počas vyučovacej hodiny. Bez pripraveného debuggeru ukážte kontrolu zdrojového kódu, terminálu a očakávaného výstupu.

5. Praktická úloha

Úloha A – preložte a spustite

Uložte správny krátky program do súboru main.c. Preložte ho v režime C17 a spustite ho vo svojom prostredí.

#include <stdio.h>

int main(void) {
    printf("Test sa zacina.\n");
    printf("Program bol spusteny.\n");
    return 0;
}

Kritérium úspechu: preklad skončí bez chyby a po spustení sa zobrazia dve očakávané správy v správnom poradí.

Úloha B – nájdite syntaktickú chybu

V nasledujúcom programe nájdite problém, prečítajte si diagnostiku GCC, opravte kód a znova ho preložte.

#include <stdio.h>

int main(void) {
    printf("Kontrola prekladu\n")
    return 0;
}
Kontrola riešenia

Za volanie printf treba doplniť bodkočiarku: printf("Kontrola prekladu\n");.

Úloha C – nájdite chybu v zadaní

Upravte text v správne sa prekladajúcom programe tak, aby sa zobrazilo presne: Test uspesne dokonceny. Skontrolujte, či skutočný výstup zodpovedá zadaniu.

Kritérium úspechu: program sa preloží a vypíše zadanú vetu bez nežiaduceho ďalšieho textu.
